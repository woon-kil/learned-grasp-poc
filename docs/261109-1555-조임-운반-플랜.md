작성: 2026-11-09 15:55 KST, v2 같은 날. 실기 쓰기 0건. 입력: `docs/261109-1555-G0b-2-20mm-운반-결과.md`, `docs/261109-1519-직립-운반-낙하-이슈보고서.md`. v2는 Codex 1차 검토(BLOCKING 2, MAJOR 4, MINOR 2)를 반영했다.

## 목표

파지 높이 20 mm에서 `close_sdk`를 높이면 `park` 운반 때 블록이 돌지 않는지 시험해, **시험한 후보 중** 통과하는 가장 작은 닫기 값을 정한다. 변수는 `close_sdk` 하나다.

## 앞 탐색과의 관계

플랜 `docs/261109-1519-파지-깊이-운반-플랜.md`의 깊이 탐색은 **20 mm 실패, 17.5 mm 미실시로 종료**하고 이 탐색으로 대체한다. 그 플랜의 순서를 이행한 것이 아니라 바꾼 것이다. 22.5 mm 낙하와 20 mm 회전 기록은 그대로 둔다. 이 스크리닝 결과를 G0b 평가에 섞지 않는다.

## 현재 상태 (As-Is)

- 구성 4: z 20 mm, `close_sdk` 147, G0a 통과. `park`에서 블록 회전, 기울어진 채 놓임(1회).
- 조임을 높이면 힘과 전류가 는다는 것은 가설이다. 파지력과 온도를 잰 적이 없다.
- 코드에 `close_sdk` 상한이 없다.
- 쥔 상태 조회를 기록한 적이 없다. 빈 손 조회 145(명령 147, 1회)는 파지력이나 간격의 근거가 아니다.
- 닫은 손끝 높이를 실측한 적이 없다. 계산 겹침 18~23 mm와 관찰 상단 1/3이 다른 원인도 모른다.

## 빈 손 닫기 위험

놓친 채 닫으면 손끝이 명령값까지 더 나오는 것으로 계산한다. `fit_trial` 항목(r_index 4, r≈140, 모델 z 19.42 mm)의 빈 손 닫은 손끝 추정, 작업대 위 mm:

| `close_sdk` | 비율 맞춤 계산 | 보수 계산(돌출 +4.2 mm) |
| --- | --- | --- |
| 147 | 6.1 | 1.9 |
| 155 | 3.8 | −0.4 |
| 160 | 2.5 | −1.7 |

보수 계산이 음수이므로 **이 높이에서 바로 닫지 않는다.** 위에서 닫아 실측한 값으로 여유를 입증한 뒤에만 내려간다.

## 시험 계약 (실행 전 커밋, 결과를 본 뒤 바꾸지 않음)

후보는 **155**, 그다음 **160**이고 **160을 넘지 않는다.** 후보마다 구성 버전을 올린다(155는 구성 5, 160은 구성 6). 위치는 r≈140, J1 90, J5 90이다.

### 1단계: 빈 손 닫기 단계 하강 (`close-check`)

세션 `G0b-3`, 블록 없음. 오프셋 **+15 → +5 → 0** 순서이고 앞 단계 관찰을 `session observe`로 기록해야 다음으로 간다(기존 `require_previous_observation`). 단계마다 `park→hover→grasp→닫기→머묾 20초→열기→hover→park`, 쓰기 7회, 합 21회, `max_writes` 22.

사용자는 **시작 전 보드에 자를 세워 두고**, 머무는 동안 손을 넣지 않고 눈으로 **닫은 손끝과 보드 사이 간격을 mm로 읽는다.** 눈금 판독 오차는 ±1 mm로 본다.

내려가는 조건: **(읽은 간격 − 실제 모델 FK 하강량) ≥ 3 mm.** 명목 하강량이 아니라 표 항목의 FK 차이를 쓴다.

| 지금 (모델 z, 기울기) | 다음 (모델 z, 기울기) | FK 하강량 | 다음 조건 |
| --- | --- | --- | --- |
| +15 (34.63 mm, 10°) | +5 (24.98 mm, 6°) | 9.65 mm | 간격 ≥ 13 mm |
| +5 (24.98 mm, 6°) | 0 (19.42 mm, 7°) | 5.56 mm | 간격 ≥ 9 mm |

조건을 못 맞추거나 **눈금을 읽지 못하면** 내려가지 않고 그 값은 이 높이에서 사용 불가로 끝낸다. 읽으려고 전원 차단 위치를 벗어나거나 처짐 범위로 몸을 숙이거나 유지 시간을 늘리지 않는다. 전원 차단 위치에서 읽을 수 없으면 시작 전에 알려 주고 관찰 방법을 다시 정한다.

실행 전 `fit_trial`의 J1, J5가 90인지 확인한다. 현재 구성의 범위 중앙값이 90이다.

### 2단계: 운반 (`carry-test`)

1단계 0 오프셋이 접촉 없이 끝난 뒤, 세션 `G0b-4`, 고정 최대 3회, `--hold-sec 5`, 쓰기 33회와 끝 저자세 3회, `max_writes` 38. 시작 전 사람이 블록을 놓는다. 시도마다 답한다: 낙하, 미끄러짐·회전, 작업대 접촉, 잡은 높이, 내려놓기, 이상음, 발열.

### 유지 시간과 발열

공식 서보 사양을 찾지 못해 허용 시간을 근거로 정할 수 없다. 아래는 보수적으로 고른 운영 한도이고 안전 입증이 아니다.

| 항목 | 한도 |
| --- | --- |
| 닫기부터 열기까지 시도당 | 30초 이하. 시퀀스 계산 24.6초(이동과 `--hold-sec 5`, 구성의 이동시간 기준). **닫기~열기 시간을 테스트로 고정한다.** 시퀀스가 정상이면 30초에 닿지 않는다 |
| 빈 손 단계 | 약 24초(머묾 20초). 3단계 약 72초 |
| 30초 대응 | 운반과 빈 손 단계 공통. 사용자가 **닫히는 순간 타이머를 시작하고, 30초가 되어도 그리퍼가 열리지 않으면 즉시 전원을 차단한다.** 시도 종료를 기다리지 않는다. 정상 소요는 약 25초다. 빈 손 단계의 20초 머묾은 정상 동작이므로 정지 시간으로 판단하지 않는다 |
| 시도 사이 쉼 | 60초 이상. 다음 시도는 앞 프로그램이 끝난 뒤에만 시작한다 |
| 세션 누적 닫힘 | 90초 이하(운반 3회 약 74초) |
| 세션 사이 쉼 | `G0b-3` 끝과 `G0b-4` 시작 사이 5분 이상 |
| 실행 중 관찰 | 이상음, 냄새, 떨림은 즉시 전원 차단 |
| 온도 확인 | 온도 읽기가 없다. **프로그램 종료는 전원 차단이 아니므로 전원이 있는 동안 팔과 서보를 만지지 않는다.** `G0b-4` 끝에 1회만 본다. 비접촉 온도계가 있으면 전원 차단 위치에서 재고 기록한다. 없으면 `session descend`로 저자세까지 간 뒤(쓰기 3회, 그리퍼 개방) 전원을 차단하고, 팔이 안정된 것을 본 뒤 서보 몸체를 짧게 만진다. **잡고 있기 어려울 만큼 뜨거우면 탐색 중단.** 이 기준은 안전 입증이 아니라 중단 신호다 |

**쥔 채 전원 차단할 때**: 손으로 블록을 받치지 않는다. 블록은 떨어지게 두고, 손은 전원 차단 위치에 두어 처짐 범위 밖에 둔다. 작업대 위 낙하 범위에서 부서질 물건은 시작 전에 치운다. 차단 뒤 팔과 블록이 멈춘 것을 확인하고 나서 접근한다. 프로그램이 예외로 끝나면 서보는 닫힌 채 힘을 유지할 수 있고, 자동 복구 이동은 없다. 전원 차단이 기본이다.

**G0b 진입 조건**: G0b는 쥔 시간이 훨씬 길다(시도 약 40초 중 절반 이상 추정). 이 값으로 G0b 유지 패턴을 재현한 열 확인을 별도 플랜으로 통과하기 전에는 G0b에 들어가지 않는다.

### 사건 처리

| 사건 | 처리 |
| --- | --- |
| **작업대 접촉** (빈 손 포함) | 전원 차단, **조임 증가 탐색 중단.** 더 높이지 않는다 |
| **낙하** | 전원 차단, 그 값 실패. 다음 값은 새 승인·새 기록 |
| **미끄러짐·회전** | 전원을 끊지 않고 내려놓기까지 마친 뒤, 그 값 실패. 다음 값은 새 승인·새 기록 |
| **블록 변형, 튐** | 전원 차단, 조임 증가 탐색 중단 |
| **이상음, 냄새, 과열, 떨림** | 전원 차단, 조임 증가 탐색 중단 |
| **미완료** (적재 시간 초과, 조회 불일치, 연결 단절) | 세션 중단. 후보를 올리지 않는다. 원인을 확인한 뒤 **같은 값**을 새 승인·새 세션의 별도 실행으로 처음부터 할 수 있다. 앞 기록을 대체하지 않고 둘 다 결과 문서에 남긴다. 적재 시간 초과는 시도가 시작되지 않으므로 기록에 시작이 없고, 결과 문서에 적는다 |
| 3회 모두 사건 없음 | 그 값 스크리닝 통과 |

- 실패나 미완료를 지우거나 다시 세지 않는다. 같은 값의 실패를 재시도하지 않는다. 위 미완료의 별도 실행만 예외이고, 그 전에 실패로 판정된 값은 해당하지 않는다.
- 빈 손과 운반은 세션 폴더로 기록을 나눈다.
- 합격 표본이 아니다. G0b 분모에 넣지 않는다.
- 160도 실패하면 멈추고 다음 변수를 새 플랜으로 정한다.

## G0a 근거의 범위

`close_sdk`는 구성 값이므로 버전을 올린다. **유지하는 것은 개방 경로의 드라이런 근거뿐이다.** 드라이런은 개방 상태로 돌고 닫기를 쓰지 않는다. `verified_g0a: true`는 새 닫기 값의 안전을 뜻하지 않는다.

유지 조건: 표 해시 `58c35bcb…`, `park`, `open_sdk`, `motion`, 작업대·보드·장착 상태가 G0a-7과 같을 것. 구성 변경 때 앞의 네 값을 대조해 결과 문서에 적고, 장착 상태는 사용자에게 확인한다. 다르면 false로 내리고 G0a를 다시 한다.
