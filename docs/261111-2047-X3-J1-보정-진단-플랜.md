# X3 J1 오프셋 보정 진단 플랜 (v2, **보류**: 손끝 축 검출이 회전한 손에서 불안정)

작성: 2026-11-11 KST, v2는 같은 날(advisor 지적 + 사용자 관찰 반영). 사용자 지시 「푸시하고 제안 진행」(X2 A 결과의 제안). **승인 전이다.** 앞선 결과: `docs/*X2-A-횡방향-오프셋-24시도-결과.md`(24/24, J1 보정 진단 −5.4°가 문턱 3°를 넘어 B 보류).

## 1. 문제: 이전 진단(놓인 뒤 방향 잔차)은 보정과 닫기 회전을 구분하지 못한다

- 사용자 관찰: 「물체와 양 손끝의 간격이 다르면 grasp 때 물체의 위치가 한쪽 손끝에 밀리면서 바뀐다.」 X2 A가 이를 확인했다(놓인 블록 J1 − 손 J1이 Δ와 무관, 재중심).
- 먼저 닿는 한쪽 손가락이 블록을 밀면 **블록을 돌리는 모멘트**도 생긴다. 그 회전의 부호는 Δ의 부호를 따를 수 있다. 놓인 뒤 방향 잔차는 이 닫기 회전을 포함하므로, 큰 표본을 더해도 J5 보정 오류와 닫기 회전을 가를 수 없다(advisor 지적). X2 A에서 +1 그룹만 어긋난 것도 이와 맞는다.
- 이월 기울기 s(집기 어긋남이 놓인 방향으로 이어지는 정도)도 잰 적이 없다. 따라서 「D < −3이면 보정을 줄인다」는 규칙은 옳은 보정을 「고칠」 수 있다. **이전 X3 초안은 폐기한다.**

## 2. 새 진단: 닫히기 **전** hover 사진으로 손-블록 어긋남을 직접 잰다 (쓰기 0, 사진만)

hover에서 하강 전에 사진 한 장을 찍는다(`chain --hover-photo`, 쓰기 없음). 분석:
- **ψ_pick = 블록 긴 변 각도(park 사진) − (손끝 축 각도 + 90°)**. 손끝 축 = 열린 손의 두 손가락 끝(각 손가락의 아래 끝 띠)을 이은 직선의 영상 각도(`src/learned_grasp/hand_tips.py`). 닫히기 전이므로 닫기 회전과 이월에 영향받지 않고 **J5 보정만** 반영한다. 이는 B의 안전에도 직접 쓰이는 값이다(하강 때 손과 블록의 실제 어긋남).
- **좌우 비대칭** = (블록 중심 − 손끝 중점)을 손끝 축 방향으로 투영한 화소. L1 맵을 거치지 않은 실제 횡방향 어긋남이다(사용자 질문 「hover가 정확히 가운데가 아닌 것 같다」에 대한 직접 측정).
- 카메라 기하의 상수 편향(시차, 영상 각도 원점)은 **Δ 사이 차이**에서 빠지므로 차이를 판정에 쓴다.

**쓰기 없는 사전 확인**: 같은 hover 자세의 사진 30장(`runs/H2-1/hover`)에서 손끝 검출 30/30, 축 각도 표준편차 **0.03°**, 간격 표준편차 0.19 px(정지 영상 재현성이며 팔 재방문 변동은 별개: H2-1 재방문 차이 0.4~0.5 px ≈ 0.4°). 블록 방향은 같은 사진에서 약 1~2°(최소 외접 사각형) 불확실하다. 판정 정밀도는 블록 방향 측정이 정한다(차 D의 표준오차 ≈ 2°/√8 × √2 ≈ 0.7°).

## 3. 설계

- 기존 `chain --x2` 연쇄 + `--hover-photo`. 일정 `config/x3.json`: Δ −1, 0, +1 각 8번(24시도), `config/x3_sanity.json`: [0, +1, −1](3시도). 놓는 손 J1 공칭. 쓰기 약 241회(24시도)·31회(sanity). 쉼 10분 × 2. 블록 모양 점검은 재설정본.
- **판정 변수(사전 고정)**: D_pick = ψ_pick(Δ=+1) 평균 − ψ_pick(Δ=−1) 평균과 95% 신뢰구간(X3만으로 결정, X2 A는 이 진단에 쓰지 않음: 평균으로의 회귀 편향 방지).

| 결과 | 해석 | 다음 |
| --- | --- | --- |
| 구간이 0을 포함하고 \|D_pick\| ≤ 1.0° | 보정이 맞음. 놓인 뒤 잔차의 비대칭은 닫기 회전 | B(±2°)를 별도 승인으로 진행 |
| 구간이 0을 제외, D_pick > +1° | 보정 부족 또는 부호 오류(보정 없음 +2.6°, 부호 반대 약 +5.2°에 가까운 쪽을 본다) | 보정 계수를 사진 값으로 맞춰 별도 계획·재진단, B 보류 |
| 구간이 0을 제외, D_pick < −1° | 과보정 | 같음 |
| 구간이 0을 포함하나 \|D_pick\| > 1° | 표본 부족 | 표본 추가 여부 결정(최대 1회) |

(D_pick 부호는 영상 각도 규약에 따르므로 부호 해석표는 sanity 3시도의 Δ = ±1 값으로 방향을 먼저 확인한다.)

- 부가: 좌우 비대칭 대 명령 횡방향(`lateral_true_mm`) 기울기(기대 약 ±1.1 px/mm), 잔차 표준편차 = L1 맵을 거치지 않은 hover 횡방향 오차. 성공/실패와의 관계. 놓인 뒤 방향 잔차와 닫기 회전의 분리는 부가로만 본다.

## 6. 보류 결정 (같은 날, advisor 2차 검토 뒤 쓰기 없는 확인)

- advisor 2차 검토: (1) 손끝 ROI가 H2-1 hover 자세 한 곳에 맞춰져 있어 X3의 다른 자리에서는 손끝이 창 밖이다 (2) 서로 다른 자리 8 대 8의 ψ_pick은 손 yaw 모델 오차(자리마다 3~4°)가 섞여 표준오차가 약 1.7°라 ±1° 판정이 불가능하다(위 2절의 0.7°는 틀림) → **같은 블록을 놓고 hover 자세만 바꿔 찍는 쌍 비교(hover 스윕: 닫기 없음)** 로 바꾸라는 권고.
- **쓰기 없는 확인(방법의 전제)**: 같은 손끝 검출을 같은 사진에서 ROI만 바꿔 돌리면 결과가 크게 달라진다. X1 chain-003 hover 사진(J5 114): ROI A에서 축 각도 10.5°, 블록 중심 기준 ROI B에서 14.5°(오른 손가락 아래 끝이 6 화소 다름). H2-1 hover 사진(J5 90)의 2.4°와 비교하면 J5가 +24° 변할 때 축이 +8° 또는 +12° 바뀌어, 영상에서의 민감도가 **0.35~0.5 영상°/J5°**로 기대(약 1.1°/°)보다 낮고 검출 방식에 따라 흔들린다. 「가장 아래 어두운 화소」는 손이 회전하면 손가락 끝점이 아니라 손가락 몸통·그림자 가장자리가 되기 때문으로 보인다(가설).
- **결론**: 손끝 축 각도로 ψ_pick을 재는 방법은 **지금 구현으로는 믿을 수 없다.** 다음 중 하나가 전제다: (a) 손끝 템플릿 또는 손가락 끝의 고유 특징 검출로 재구현하고 J5 ±5° 스윕으로 민감도 ≥ 0.8°/°를 먼저 확인 (b) 손목 DaBai 카메라(L3 경로)로 손 좌표계에서 블록을 직접 본다. 둘 다 별도 계획이 필요하다.
- **X3와 B는 보류한다.** 근거: X2 A에서 ±1°(실제 횡방향 ±4.5 mm)까지 24/24 성공, 쥔 블록 재중심 확인, 걸림 위험 모의 10~17%(B). B를 하려면 먼저 위 (a) 또는 (b)로 hover 간격을 직접 재는 것이 안전상 필요하다.
- 코드: `hand_tips.py`, `run_chain(--hover-photo, --replaced)`, `x3_summary.py`, `x3_schedule.py`는 구현·시험(`pytest` 352 passed) 상태로 남기되 X3는 승인 요청하지 않는다.
