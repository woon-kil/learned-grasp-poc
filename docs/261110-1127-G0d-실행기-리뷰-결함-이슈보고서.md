# G0d 실행기 리뷰 결함 이슈보고서

작성: 2026-11-10 11:27 KST. 쓰기 0건. 원문 `docs/261110-1127-G0d-실행기-코드리뷰-원문.md`.

## 현상

G0d 실행기를 Fake 시험 237개 통과, 변이 5종 검출 상태로 커밋했다. 이어서 Codex 코드 리뷰를 받았는데 **BLOCKING 3건, MAJOR 7건**이 나왔다. 반영본을 advisor로 재검토하자, 새로 넣은 경로에서 BLOCKING 1건과 MAJOR 2건이 더 나왔다. 이와 별개로 첫 Codex 리뷰 호출은 결과 없이 끝났다.

```text
BLOCKING — 닫힘 한도 검사와 실제 전송 사이 경쟁
BLOCKING — 집기 판정 사진의 카메라 이동을 검사하지 않고 복귀
BLOCKING — 실제 닫기 10회 기준의 쉼 경계가 없음
BLOCKING 3건
```

```text
$ wc -l .../rollout-2026-11-10T11-01-51-...jsonl
      29   (도구 실행 두 번 만에 끊긴 세션)
```

## 원인

1. **만료 경쟁:** 만료를 스레드가 세우는 깃발로만 판단했다. 그런데 검사와 원격 전송 사이에는 계수 파일 `fsync`가 있다. 스레드가 늦게 깨는 경우도 시험하지 않았다.
2. **판정 사진 기준:** 「사진마다 기준 검사」(플랜 55행)를 배치 사진에만 적용했다. 집기 뒤 판정 사진은 변화·노란 화소만 봤다.
3. **쉼 묶음:** 플랜 172행을 부하 추산 문장으로만 읽었고, 실행 경계로 만들지 않았다.
4. **집계 정의의 공백:** 흩어짐에 비교 단계 표본이 섞였다. 각도는 중앙값으로 계산했다. 복귀 사진은 노란 화소 52 기준에서 빠졌다.
5. **새 경로의 구멍:** 쉼 묶음을 넣자 묶음 경계가 복귀 쌍과 기준 표본을 깼다(셀 0의 기준 표본이 5개가 됐다). 이를 막으려고 준비 순환을 넣었지만, 준비 순환이 실패해도 기록에 남지 않아 이어하기로 우회할 수 있었다.
6. **Codex 호출 실패:** Codex 출력을 `| head -150`으로 잘라 받았다. 150줄이 지나 파이프가 닫히자 Codex가 SIGPIPE로 종료됐다. 세션 기록은 29줄이었고 최종 답이 없었다.

공통 원인은 시험 범위다. 시험은 Fake 장치에서 처음부터 끝까지 한 번에 도는 흐름만 덮었고, 묶음 이어하기·시간 경과·`run_g0d` 연결은 덮지 않았다. 변이도 플랜 216행 목록 5종만 확인했다.

## 수정

- **커밋 `4de6569`:**
  - 만료를 단조 시계로도 판정한다. SafeArm과 전송 직전 드라이버(`WatchedDriver`)에서 두 번 막는다.
  - `_judge`가 판정 사진의 기준 마커를 확인하고, 어긋나면 쓰기 없이 멈춘다.
  - 실제 닫기 10회 전에 블록을 내려놓고 멈추며, 같은 명령으로 잇는다.
  - 답 마감을 질문 게시 전에 고정하고, 해제 직전에 다시 확인한다.
  - 기준은 spread 단계로만 잡고, 각도는 원형 평균으로 계산한다.
  - 기록을 기준점·시험표·spread 해시에 묶는다.
  - 복귀 중에 멈추면 그 변형을 미완료로 둔다.
- **커밋 `cdff434`:**
  - 준비 순환이 멈추면 incomplete로 기록하고, 곁가지 실패도 집계한다.
  - `held` 답 뒤에는 이어하기를 거부한다.
  - `run_g0d` 연결 시험을 넣었다.
  - 복귀 단계는 셀별로 |δ|가 가장 작은 것을 쓴다.
  - 닫힘 시간을 추산하고, 플랜을 v10으로 개정했다.
- **Codex 호출:** `-o <파일>`로 최종 답만 받고 표준 출력은 버린다.

```text
변이 13종 모두 검출, 원복 뒤 259 passed
닫힘 최대(가짜 시계, 사람 답 대기 제외): G0d-0 19.9초(67구간), G0d 1차 19.9초(162구간)
```

## 교훈

- **시험 흐름:** 실행기 시험은 실제 운영 흐름대로 짠다. 묶음 끝, 새 세션, 이어하기, 시간 경과를 넣는다. 한 번에 끝까지 도는 시험만으로는 이어하기 경로의 우회를 보지 못한다.
- **새 경로의 기록:** 결함을 고치려고 새 경로(준비 순환)를 넣으면, 그 경로가 실패하거나 멈췄을 때 집계와 이어하기에 어떻게 남는지를 같은 커밋에서 시험한다.
- **플랜 문장 대조:** 「~로 센다」, 「사진마다」 같은 문장은 실행 경계나 검사로 옮겼는지 하나씩 대조한다.
- **Codex 출력:** `head`로 자르지 않는다. 최종 답은 `-o`로 받는다.
- **교차 검토:** advisor 대체는 같은 계열이다. 쓰기 안전 코드는 Codex 재리뷰를 `G0d-0` 승인의 선행 조건으로 둔다(2026-11-13 이후).
