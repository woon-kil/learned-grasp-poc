## 1. 목표

고정 환경·물체 1종·DOFBOT Pro 1대에서, **명시적 손–눈 변환을 추정하지 않고** 로봇이 스스로 수집한 데이터로 영상→파지 명령 대응을 학습해 물체를 집어 올리는 것을 제한적으로 실증한다.

포트폴리오 문장(T1 합격 시에만 사용):

> 저가 5축 팔과 고정 RGB 카메라에서, 명시적 손–눈 변환 추정 없이 로봇이 직접 수집한 데이터로 영상→파지 명령 대응을 학습했다. 사람이 시험표대로 놓은 물체 30회 중 n회를 집어 올렸다(Wilson 95% 구간 병기). 같은 시험에서 고전 비전 기준선과 비교했다.

주장하지 않는 것: 보정의 일반적 대체, 소량 표본 효율 우위, 임의 물체 일반화, 산업 수준 신뢰성.

## 3. 접근 방법

### 채택: 「놓은 자리를 다시 집기」 자기 지도 수집

1. 물체를 쥔 채 허용 자세 표의 관절 목표 `q`로 정해진 경로를 따라 내려가 놓고, 고정된 촬영 자세로 물러난다.
2. 고정 카메라로 촬영한다.
3. `q`로 복귀해 집어 올린다. 모든 시도를 성공 여부와 함께 기록한다.
4. 재집기에 성공한 표본만 학습에 쓴다. **라벨은 물체의 참 좌표가 아니라 「검증된 파지 명령 좌표」** `(r, φ, ψ)`다. `φ`는 J1 방위, `ψ`는 J5 파지 방향이다.
5. 모델은 `이미지 → (r, φ, ψ)`를 배우고, 추론값은 라벨과 같은 표를 거쳐 관절 명령이 된다.

**논리의 성립 조건**: 카메라 내부·외부 파라미터, 실물 TCP, URDF 절대 오차가 라벨에 들어가지 않는 대신, **같은 명령·같은 경로의 반복 정밀도**에 전적으로 의존한다. 놓을 때의 하중, 개방 후 미끄러짐, 재접근 백래시는 공통 모델로 상쇄되지 않는다. 이 조건은 G0에서 실측하며, 통과 범위 안에서만 위 포트폴리오 문장을 쓴다.

Form2Fit(분해의 시간 역전 자기 지도)과 Transporter 계열(평면 작업 표본 효율)은 접근의 동기일 뿐, 이 팔에서의 타당성 근거가 아니다. 같은 방식을 저가 5축 팔에서 검증한 자료는 찾지 못했다.

통신은 SSH 표준입출력 위의 JSON 줄 프로토콜이다. 새 포트를 열지 않는다. Jetson 서버는 표준입력이 끊기면 이후 명령을 폐기하고 종료하며, 재개는 새 세션 승인으로만 한다. 이미 전송된 서보 이동은 이 동작으로 멈추지 않으므로 감독자가 전원으로 대응한다.

| 항목 | 결과 | 의미 |
| --- | --- | --- |

| 서보 1° 위치 민감도 | 관절별 2.2~3.5 mm | 양자화 영향이지 반복 정밀도 실측이 아니다 |
| 그리퍼 | SDK 135에서 손끝 간격 32.37 mm, 블록 폭 29.89 mm | 더 넓은 개방의 실측이 필수 |

모델 TCP와 손가락 사이 후보점은 약 43 mm 떨어져 있어, z 값으로 작업대 높이를 추정하지 않는다.

**그리퍼 돌출과 파지 높이 기준 (v2.2)**: 이 그리퍼는 평행 링크 구조라 닫으면 손끝이 나오고 열면 들어간다. SDK 100에서 블록 접촉까지 약 16~20 mm로 계산했고 실측은 아니다(`docs/261109-1257-그리퍼-돌출-계산.md`). 파지 높이는 **닫은 손끝** 기준으로 정한다.

- 구성 3의 파지 높이는 모델 TCP 22.5 mm다. r≈140 mm 한 위치에서 한 번 시험해 정했다(`docs/261109-1410-G0b-0-집기-높이-결과.md`).
- 구성은 명목 높이 17.5 mm 미만을 거부한다. 그 아래에서 닫으면 작업대를 누를 수 있다는 추정 때문이다. 17.5 mm에서 닫아도 된다는 보증은 아니다.
- G0a 드라이런은 그리퍼를 연 채로 돈다. 위치별 닫은 손끝 관찰은 G0b 첫 통과에서 처음 이뤄지고, 시드 1 시험표에 없는 표 항목 3, 7번은 그때도 관찰되지 않는다.

## 7. 시험 계약 (G3)

G3 전에 계약·모델·설정·데이터 분할의 SHA-256과 코드 커밋을 `docs/`에 기록한다. 시험 데이터로 튜닝하지 않는다.

| 항목 | 고정 내용 |
| --- | --- |
| 시험표 | 시드로 사전 생성. G0에서 확정한 작업 영역(`r, φ, ψ`) 안에서 층화. 수집에 쓰지 않은 세션 |
| 배치 | 인쇄 격자·방향 표식에 맞춰 사람이 놓고 매 시행 초기 사진 저장 |
| 방법 순서 | 시행 쌍마다 모델·기준선 순서를 시드로 무작위화 |
| 재시도 | 금지. 분모는 시험표 전체 |
| 성공 | 연속 영상에서 물체와 작업대의 틈이 보이고 5초 유지. SDK 반환만으로 판정 금지 |
| 판독 불가 | 가림 등은 `UNREADABLE`로 따로 세고 성공이 아니다 |
| 집계 | 성공, 실패, `REJECT`, `UNREADABLE`. 전체 성공률, 실행 비율, 실행 시 성공률, 잘못 실행 사례, Wilson 95% 구간 |

| 시험 | 조건 | N | 용도 |
| --- | --- | --- | --- |
| T1 | 학습과 같은 물체·조명 | 30 | **합격 판정**(≥24) |
| T2 | 지정 여백 구역에 방해물 2개, 시드 고정 조명 변화 | 20 | 기준선과 짝 비교, 합격선 없음. 목표는 항상 노란 블록 |

24/30의 Wilson 95% 구간은 약 62.7~90.5%다. 사전 정한 PoC 합격선일 뿐, 실제 성공률 80% 이상의 입증이 아니다.

**프로젝트 완료**는 G3·G4 수행과 보고이고, **PoC 합격**은 T1 통과다. 불합격은 원인 분석과 함께 결과물로 남기며 합격으로 표현하지 않는다.

## 8. 모델과 기준선

**모델**: 고정 ROI를 320×240으로 줄인 RGB → ResNet18 앞단 → 특징맵 → (A) spatial soft-argmax 좌표+MLP 또는 (B) 전역 평균+MLP → `(r, φ, sin 2ψ, cos 2ψ)`. A와 B는 G1의 같은 분할에서 비교해 정하고 G3 전에 고정한다. 180° 대칭 파지를 가정하므로 물체 대칭성은 G0d에서 확인한다. 기하 증강은 라벨을 깨므로 금지하고 밝기·색만 쓴다. 단일 모델로 시작한다. 앙상블은 G1에서 개선이 검증될 때만 추가한다.

**실행 검사(모델 불확실성과 독립, 필수)**: 예측이 작업 영역 안, 허용 표에 해당 항목 존재, 프레임 신선도 ≤2초, 방향 벡터 노름 ≥0.5. 하나라도 실패하면 `REJECT`.

**기준선**: 같은 라벨로 적합한 고전 파이프라인이다. HSV 마스크 → 최소 외접 사각형 → 다항 회귀로 `(r, φ)`, 각도 특징→`(sin 2ψ, cos 2ψ)` 회귀. 평상 조건에서 학습 모델과 비슷할 수 있고, 그 결과도 그대로 보고한다.

## 9. 안전

기존 프로젝트의 위험 기록을 강제 규칙으로 옮긴다. 일반적인 작업 영역 봉투만으로 안전을 주장하지 않는다.

- **무인 수집은 이번 PoC에서 제외한다.** 모든 수집·시험은 전원 차단 담당자가 있는 감독 세션이다.
- **허용 자세 표**: 실행 가능한 `(J2, J3, J4)`는 `r`로 색인되는 표의 항목뿐이다. 항목마다 대기(hover)·파지(grasp) 두 자세를 가진다. J1·J5는 G0a에서 확정한 구간만 허용한다.
- **허용 전이**: `park→hover→grasp→hover→park`만 허용한다. 전이마다 관절 조합, 이동시간 **하한**, 1회 이동각 상한을 정의한다. 표는 파일 해시로 고정하고, 변경 시 G0a를 다시 한다.
- 모든 쓰기는 `safety.py` 한 곳을 통과하며, 실패하면 전송하지 않는다. 실장치 어댑터는 세션 승인 토큰 없이는 쓰기를 거부한다.
- `arm_driver`를 실행하지 않는다. 생성자가 서보 6개를 쓴다.
- 조회값을 목표로 쓰지 않는다. 복귀는 원래 쓰기 목표를 재전송한다. `Arm_Lib`의 `int` 절삭으로 명령과 반환이 다를 수 있다.
- 파지 자세의 J2 하한은 G0a 빈 그리퍼 하강으로 정한다. 기존 83° 하강의 눌림 기록은 다른 자세 값이므로 그대로 쓰지 않는다.
- 정지 수단은 **전원 차단**이다. 소프트웨어 정지와 토크 해제는 정지 수단으로 간주하지 않는다. 전원 차단 시 팔이 처지므로 처짐 범위에 손을 넣지 않고, 쥔 물체용 낙하받이와 낮은 이동 높이를 쓴다. 거동은 G0a에서 빈 그리퍼로 먼저 확인한다.
- 낙하·스냅샷 실패·카메라 기준 이미지 변화·연결 단절은 다음 명령을 막고 세션을 끝낸다. 감지 지연과 누락은 G0e에서 측정하며, 감지는 낙하 방지가 아니다.
- 실기 세션은 대상, 명령 범위·횟수, 관찰, 중단 조건을 한 번에 승인받는다. 범위 밖 명령은 새 세션이다.
- p620은 공유 서버다. 다른 프로젝트 컨테이너를 멈추거나 지우지 않고, USB 사용 충돌을 먼저 확인한다.

### 데이터 규칙

모든 시도에 이미지, 원래 `q`, 복원 `q′`, 성공 여부, 실패 이유, 사람 개입 여부, 구성 버전을 저장한다. 학습 채택은 **사람 개입 없이 재집기에 성공한 표본**이다. 셀별 채택률을 보고해 어려운 위치가 사라지는지 확인한다. 분할은 셀 또는 세션 단위이며, 연속 프레임을 무작위로 나누지 않는다. 기존 프로젝트의 증거는 학습·평가에 쓰지 않는다.

데이터셋·모델·학습·기준선·평가 코드는 **G0 통과 후 S1**에서 만든다. 핵심 물리 가설이 깨지면 쓸모없는 코드이기 때문이다. 기존 저장소에서는 FK 계산, `classify_sdk_return`, USB·컨테이너 보호 패턴만 다시 작성해 가져온다. 과거 각도, 손–눈 변환, 증거는 가져오지 않는다.

### S0 Check 기준

1. `pytest` 전체 통과, 실행 출력을 체크 문서에 기록
2. FK가 기존 `dofbot_fk`의 대표 자세 값과 일치, 표 전수에서 `IK(FK(q))=q`
3. 표 밖 자세·허용되지 않은 전이·이동시간 하한 미달·토큰 없는 쓰기가 Fake 어댑터에 도달하지 않음
4. Fake 위 G0b 실행기가 시드 고정 시험표로 동작하고, 중단 후 재개해도 시도 기록이 유실·중복되지 않음
5. JSON 줄 서버가 입력 단절 시 이후 명령을 폐기, `arm_driver` 미사용을 정적 테스트로 확인
6. 장치 명령 0건

## 11. Pre-mortem

| 실패 원인 | 영향 | 예방·대응 |
| --- | --- | --- |
| 놓을 때 블록이 튀거나 돌아 명령과 어긋남 | 재집기 실패, 라벨 잡음 | 낮은 높이에서 천천히 개방. G0b에서 이미지 전후 차이 측정 |
| 서보 백래시로 경로에 따라 자세가 달라짐 | 반복 정밀도 부족 | 항상 같은 hover 경유. G0b·G0c의 핵심 판정 |
| 양자화·오차가 허용 오차보다 큼 | 집기 실패 | 물체를 좁게, 개방을 넓게, 영역 축소 후 구성 변경 절차 |
| 낙하 미감지 | 데이터 오염, 충돌 | 그리퍼 판독+이미지 차이, G0e 판별력 실측, 감독자 상주 |
| 팔이 시야에 남음·조명 변화 | 잘못된 학습 단서 | 촬영 자세 고정, 밝기 증강, T2로 관찰 |
| 카메라·보드 이동 | 모델 무효 | 고정, 세션 시작마다 기준 이미지 비교, 변하면 세션 종료 |
| 고전 기준선이 비기거나 이김 | 학습 우위 주장 불가 | 사실대로 보고. 포트폴리오 주장은 자기 수집과 실행 실증에 한정 |
| p620 재부팅으로 USB 경로 변경 | 수집 중단 | 재연결 스크립트, 증분 저장, 재개 |
| 감독 수집 시간이 사용자 시간을 초과 | 일정 지연 | G0e 실측 후 표본 수 축소, G2 정지 규칙 4시간 상한 |
