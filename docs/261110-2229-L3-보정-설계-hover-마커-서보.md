# L3 보정 설계: observe 영상의 블록 마커 위치로 J1을 서보한다 (설계 초안)

작성: 2026-11-10 KST. **장치 명령 0건, 승인 전 초안**이다. 입력 근거는 DB-6~DB-8(`docs/261110-1953-…`, `…2105-…`, DB-8-1~4, 모델 비교, 영상 범위 분석)이다. 앞선 플랜 `docs/261110-1153-최신기술-적용-플랜-하드웨어제약만.md` §3.4의 L3(조건부)를 **측정된 사실로 구체화**한다. 이 문서는 L3를 채택하지 않는다. 채택은 아래 L3-1 결과로 정한다.

## 1.1 설계가 성립하는 조건 (먼저 확인할 것)

**공칭 블록 자리(G0b·G0c의 파지 자리, `session.py`의 `table.nearest_index(140.0)` = y 140 mm)가 DB-7 자리와 같은가를 모른다.** DB-7 자리는 사진 추정 130 mm였다(높이 시차 가능성 때문에 신뢰하지 않는다). 같으면 베이스 쪽 여유가 3 mm 안팎이라 사람이 놓는 오차(약 1.6 mm)만으로도 L3가 자주 중단될 수 있고 **설계가 쓸모를 잃는다.** DB-7이 공칭보다 약 10 mm 베이스 쪽이었다면 공칭 자리의 마커 아래 여백은 약 57 화소(18 + 39)로 충분하다. **L3-0a에서 공칭 자리에 블록을 두고 observe 영상을 한 장 찍어 이 여백을 실측한다.** 그 값이 설계의 성립 여부를 가른다.

## 2. 핵심 설계 결정

1. **영상 위치만 쓴다. PnP·거리·높이는 쓰지 않는다.** 마커 중심 화소(열 u, 행 v)만 입력이다. 법선 모호성(DB-7)과 +5% 거리 편향, 높이 불일치는 이 설계에서 문제가 되지 않는다.
2. **모델 절대 좌표 대신 기준 영상 방식을 쓴다.** 모델은 열 60 화소 어긋나 있으므로, 「블록이 실제로 파지에 성공하는 자리」에서 찍은 observe 영상의 마커 위치 `(u_ref, v_ref)`를 **시험으로 얻어** 기준으로 둔다. 보정은 기준 대비 차이만 쓴다(모델 오프셋은 상쇄).
3. **횡방향은 J1 서보**: `e_u = u − u_ref`(화소) → 횡방향 오차 mm = `e_u / 3.75`(부호: 블록이 사용자 오른쪽이면 열이 줄었다). J1을 1°씩 돌려 `e_u`를 줄인다. 카메라가 `Arm4_Link`에 붙어 있어 J1 회전은 영상 열을 직접 움직이므로 **그 자리에서 재촬영으로 수렴을 확인하는 닫힌 고리**다. 모델 환산은 거리 140 mm에서 J1 1° ≈ 2.4 mm ≈ 9 화소다(L3-0에서 실측).
4. **앞뒤(r) 방향은 표 행 선택**: `y_est = y_ref − (v − v_ref)/4.03`로 추정하고 표에서 손끝이 가장 가까운 행(`r_index`)을 고른다. r 방향은 손가락이 지나도 블록이 남는 방향이라 여유가 다르다(HW7). 행 간격이 4~6 mm이므로 선택 오차는 반 간격 2~3 mm다.
5. **측정 분해능은 구동 분해능보다 훨씬 좋다.** 영상 0.27 mm/화소(좌우) 대비 J1 1° 약 2.4 mm다. 병목은 영상이 아니라 **1° 양자화(잔차 ±1.2 mm)** 와 사람의 재배치다. 잔차 ±1.2 mm는 HW6 한쪽 3.5 mm 안이다.

## 3. 절차 (설계)

1. `park → hover(r_index 0)`(observe), 정지, DaBai 컬러 한 장.
2. 마커 검출 실패 또는 마커 검은 사각형이 영상 가장자리에서 **임계 화소 안**(임계는 L3-0a의 공칭 자리 여백 실측으로 정한다. 참고: DB-7 성공 18 화소, DB-8-3 실패 4 화소)이면 **중단하고 사람 호출**(블록이 베이스에 너무 가깝다). 자동 이동 없음.
3. `e_u`가 임계(예: ±5 화소) 안이면 보정 없이 진행. 밖이면 J1을 `round(e_u/9)°` 이동(최대 ±4°, 한 번에 1~2°씩), 재촬영, **최대 3회**. 수렴하지 않으면 중단.
4. `y_est`로 행 선택. observe의 J1 보정값을 이어서 쓴다.
5. observe에서 `park`로 돌아간 뒤 선택한 행의 `park → hover → grasp → …`를 기존 절차 그대로 한다(**새 전이 없음**: `hover(r0)→hover(r_k)`는 새 전이라 쓰지 않고 `park`를 거친다. 쓰기 수는 늘어난다).

## 4. 시험 계획 (모두 승인 전, 각 단계 별도 승인)

| 단계 | 목적 | 내용 | 쓰기 | 판정 |
| --- | --- | --- | --- | --- |
| **L3-0a** 모델 계산과 공칭 자리 여백 | 설계 성립 확인 | (쓰기 0) ① `db3_clearance.py`에 J1 ±4°를 넣어 hover(r0)·hover(r_k)·grasp 경로의 손가락·블록 간격 계산 ② 공칭 자리 블록에 observe 한 장(DB-7과 같은 `dabai-view --r-index 0 --hover-only`, 쓰기 3회)으로 마커 아래 여백 실측 | 3 | 공칭 자리 여백이 임계를 넘는가. 넘지 않으면 L3 설계를 접거나 자세를 바꾼다 |
| **L3-0(a) 구현** | observe에서 J1을 바꾸는 명령 | 현재 `dabai-view`는 J1 인자가 없다(`--r-index`, `--hover-only`만). `--j1`을 받는 구현과 Fake 시험(쓰기 수, J1 범위 [70,110] 안 검사)이 필요하다. DB-7처럼 **구현 승인을 별도 단계로** 받는다 | 0 | pytest 통과 |
| **L3-0** 서보 특성 | J1 1°당 영상 열 이동(실측)과 순수 반복 | observe에서 J1 ±2°, 블록 고정, 영상 열 변화 측정. 블록을 건드리지 않고 observe 5회 반복해 id 7 중심 흔들림 측정 | 단계별 승인 요청서에 기록(미확정) | J1 환산이 9 화소/° 근처인지, id 7 흔들림이 1 화소 안인지(예상, 미측정) |
| **L3-1** 기준과 창 | `(u_ref, v_ref)` 확보와 허용 창 | 기존 G0b 절차로 블록 공칭 자리 파지 성공 N회의 observe 영상 위치 평균과 분산. 블록을 좌우 {0, ±2, ±4} mm로 두고 **개루프(보정 없음)** 성공률 대 영상 열. **먼저 L3-0a의 메시 계산으로 오프셋별 손가락-블록 간격을 구하고, ±6 mm는 ±4 mm에서 접촉이 없을 때만 추가한다. 첫 접촉(블록을 밀거나 걸림)이 나면 그 방향은 중단한다.** 개루프 창을 실기 실패로 찾는 대신 메시 간격으로 예측하고 작은 오프셋에서 확인하는 쪽이 안전하다 | 시험당 쓰기는 G0b 절차에서 가져온다(이 문서는 미확인) | 개루프가 어느 열 오프셋부터 실패하는가 = 창 |
| **L3-2** 서보 효과 | 같은 오프셋에서 J1 서보가 실패를 구하는가 | L3-1의 실패 오프셋에서 서보 조건 반복 | 위와 같음 | 서보 조건 성공률이 개루프보다 높고 0 mm에서 낮아지지 않음 |

판정 기준은 단계 승인 때 **사전 고정**한다(L3-1 결과 전에는 숫자로 정하지 않는다). 개루프가 ±4~6 mm(HW6 여유 안팎)에서도 실패하지 않으면 L3는 필요 없다(조건부 L3의 전제, §3.4 첫 줄).

## 5. 위험과 열린 문제

| 항목 | 내용 |
| --- | --- |
| 영상 범위 | 블록 y가 약 131 mm보다 베이스 쪽이면 마커가 잘려 검출 실패. 표 안에서 넓힐 수단이 없다(영상 범위 분석). 공칭 자리의 여백은 L3-0a에서 실측한다(§1.1) |
| 새 J1 조합 | J1 범위 [70,110]과 `Pose(HOVER, r_index, j1, j5)`는 구성에 있고 G0a 사다리가 `r_index` 양끝·중앙 × J1 양끝을 통과했다(`session.py` ladder). 그러나 J1 86~94 같은 중간값은 **개별로 시험되지 않았다**. 상위 플랜 `261110-1153` §3.1의 세 조건을 이 설계에 적용한다: ① 보정 이동은 hover 높이에서만 ② 새 하강 조합은 하중 전에 **연 손으로 먼저 지나가 본다**(L3-1 전) ③ 마진은 H3 잔차로 정한다. ## 6. 하지 않는 것

PnP 높이·거리의 사용, 표 변경(J1은 표가 허용하는 범위 [70,110] 안에서만), `hover(r0)→hover(r_k)` 직접 전이, DaBai 깊이 사용, 이 문서만으로 L3 채택, 승인 없는 실기.

## 7. 승인 요청

이 문서는 설계 초안이다. 다음을 묻는다.
1. 설계(영상 위치 + 기준 영상 + J1 서보 + 행 선택)로 가는가.
2. 그렇다면 **L3-0a(모델 계산 + 공칭 자리 observe 한 장, 쓰기 3회)** 를 첫 승인 요청서로 작성한다. 쓰기 수는 단계마다 추산해 요청서에 적는다. 각 단계는 별도 승인이다.
