## 2. 결과

| 항목 | 값 |
| --- | --- |
| 블록 윗면 마커 id 7 | **검출**(기본 파라미터, 회색·빨강 모두). 영상 행 362~462, 열 330~425, **코너 4/4 영상 안**, 변 94.8화소, PnP Z 128.9 mm |
| 보드 마커 id 1 | 검출. 행 229~285, 열 335~391, 변 54.8화소, Z 174.6 mm |
| 고정 분석 절차(높이) | 법선 각도 1.1° → **높이 38.7 mm, 기준 29.5 mm(+9.2 mm)** |

- **L3의 핵심은 확인됐다: `r_index 0` hover에서 실제 파지 위치 부근의 블록 윗면 마커가 영상 안에 전체로 보이고 기본 파라미터로 검출된다**(DB-6의 `r_index 4`에서는 영상 아래 가장자리에 40%만 보였다). 컬러 영상(`data/dabai/view/db7-hover/color.png`)에서 보드 마커는 블록 바로 위(영상 위쪽)에 선명하다.
- **모델 예측과 비교**: 플랜의 모델 예측은 블록 중심 y=140에서 마커 행 333~429, 변 94화소였다. 관측 변은 94.8화소로 **1% 안에서 일치**한다. 행은 관측 362~462로 예측보다 약 30화소 아래이고, 이는 블록이 앞 약 130 mm 추정(예측의 가정 140 mm보다 베이스 쪽)인 것과 방향·크기가 맞는다(y=130으로 계산하면 행이 약 360~460으로 관측과 3화소 안). 모델이 두 번째 자세(`r_index 0`)에서도 앞뒤 위치와 크기를 맞췄다.
- **높이 확인은 이번에 실패했다**(사전 고정 절차: +9.2 mm). 진단: 보드 마커(변 55화소)의 PnP 두 해가 재투영 오차 0.09 / 0.20으로 거의 같고(평면 모호성), 법선이 가장 가까운 해 쌍이 잘못 짝지어졌을 가능성이 있다. 보드 해 × 블록 해의 네 조합은 높이 29.7~43.6 mm로 흩어졌다. 법선 방향 오차 약 10°에 두 마커 사이 약 47 mm가 곱해져 약 8~9 mm가 생긴다. **작은 마커의 법선은 믿을 수 없다.**
- 사후 탐색(분석 정의 밖, 판정에 쓰지 않음): 마커 법선 대신 **모델 자세의 위 방향**(FK로 구한 카메라 기울기)을 써서 재투영 오차가 작은 해의 위치끼리 높이를 구하면 `db4-hover` 28.9(기준 29.5), `db5-1-hover` 42.6(46), `db5-2-hover` 59.5(59), `db7-hover` 33.5(29.5) mm였다. 오차 −0.6, −3.4, +0.5, +4.0 mm로 법선 방식보다 안정적이진 않지만 항상 큰 실패는 없었다.
- **L3의 실제 출력은 높이가 아니라 마커의 영상 위치와 크기(카메라 좌표 위치)다.** 높이 확인은 스케일 점검용이었고, 위치 대응(자세별 보정)은 이 결과의 영상 위치·크기로 한다.

## 3. 한계

- 프레임 1세트. 블록 위치는 앞 약 130 mm 추정(사진 시차 보정 개략)이고 실제 영상 위치를 DaBai로 역산하지 않았다.
- 높이 확인이 안 되어 PnP 거리의 절대 정확도는 이 자세에서 확인하지 못했다(DB-4~DB-5에서는 `r_index 4` hover로 0.3~1.4 mm 안 일치).
- 종료 후 J2 93(목표 90)은 도착 허용치 3도에 걸린 값이다. L3가 `park`와 `hover` 사이를 반복하면 반복 정밀도 문제가 될 수 있다.
- 예측 행·크기를 계획 문서에 적어 두었으므로 판독값 유도 규칙의 한계가 있다(사용자에게는 설명용으로만 알렸다).

## 4. 플랜 영향

- 하드웨어 제약판 L3는 **`observe` 자세 = 허용 표 `r_index 0` hover**를 쓰면 DaBai로 블록 윗면 마커를 전체 검출할 수 있다. 새 자세나 표 변경이 필요 없다.
