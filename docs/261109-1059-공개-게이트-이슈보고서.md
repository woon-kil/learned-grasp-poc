# 공개 게이트 이슈보고서

작성: 2026-11-09 10:59 KST. 공개 전에 발견해 해결했다. 유출은 없다.

## 현상

1. 첫 커밋에 라이선스 표기가 없는 제조사 URDF와 내부 IP가 들어 있었고, 삭제만 스테이징한 상태였다.
2. 프로젝트 `pre-push` 훅을 만들었지만 실제로는 실행되지 않는 상태였다.
3. 공개 점검이 `10.x`, `172.16.x` 내부 IP를 놓쳤다. 음성 테스트의 `172.16` 대역 사례에서 드러났다.
4. 공개 점검이 macOS에서 `rev[@]: unbound variable`로 실패했다.

## 원인

1. 커밋 시점에는 저장소를 공개할 계획이 없었다. 삭제 커밋은 이전 커밋의 내용을 지우지 않는다.
2. 전역 `core.hooksPath`가 저장소의 `.githooks`보다 먼저 적용되고, 전역 훅은 Git LFS만 실행한다. 저장소 설정 변경은 권한 분류기가 거부했다.
3. `git grep -E`의 `\b`가 macOS regcomp에서 경계로 동작하지 않았다.
4. macOS 기본 bash 3.2에서 빈 배열 전개가 `set -u`에 걸린다.

## 수정

1. 미공개 첫 커밋을 수정(amend)해 이력에서 제거했다. URDF는 FK에 필요한 수치만 `assets/kinematic_chain.json`으로 추출했고, 접속 정보는 `.env`로 옮겼다. 점검 대상을 HEAD에서 닿는 이력 전체와 커밋 메타데이터로 넓혔다.
2. 설정 변경 없이 게이트를 모두 수행하는 `scripts/safe_push.sh`를 표준 경로로 정했다. 훅은 사용자가 켜는 추가 방어선이다.
3. 경계를 `(^|[^0-9.])`로 바꾸고 `10.x` 테스트를 추가했다.
4. 빈 배열을 없애고 `"$@"`로 전달한다.

강제 푸시가 실제로 거절되는지는 시험하지 않았다. 공개 저장소에 시도할 이유가 없어 ruleset 활성 상태만 확인했다.

## 교훈

- 공개 전에는 트리가 아니라 **공개될 이력 전체**를 검사한다.
- 훅 파일이 있다는 것과 훅이 실행된다는 것은 다르다. 유효한 `core.hooksPath`를 확인한다.
- 탐지 스크립트는 금지 사례마다 음성 테스트를 둔다. 테스트가 없었다면 내부 IP 누락을 몰랐다.
