# 카메라 위치 점검

작성: 2026-11-09 11:17 KST. Gemini 335L 1장 촬영, 로봇 명령 0건. 사진은 개인 공간이 보여 커밋하지 않고 `runs/`에만 둔다.

축척은 보드 앞변 약 205 mm와 블록 묶음 약 100×67 mm로 교차 확인했다. 블록 윗면이 작업대보다 높아 약간 크게 나온다.

## 후속

1. 작업 영역에 조명을 고정한다. 창문 빛에 의존하지 않고 그림자가 팔 쪽으로 지지 않게 한다. 조명도 카메라처럼 수집과 시험 동안 고정이다.
2. 노란 블록을 작업 영역에 두고 다시 찍어 보드와의 대비, 포화, 네 모서리 시야를 확인한다.
3. 보드를 테이프로 고정한다. 움직이면 수집 데이터의 배경이 달라진다.
4. 베이스가 투명 판 위에 있는 것으로 보인다. 그렇다면 `base_link` z=0 가정(R2)이 판 두께만큼 어긋난다. G0a에서 확인한다.
5. 왼쪽의 케이블·종이와 오른쪽 천은 작업 영역 밖이라 입력 ROI에서 제외된다.

## 작업 중 이슈

**현상**: 첫 평면 맞춤 계산이 출력 없이 6분 이상 돌았다. CPU 8.8%, 메모리 14%였다.

**원인**: 수만 점 행렬에 `np.linalg.svd`를 기본값 `full_matrices=True`로 호출해, 점 수×점 수 크기의 행렬을 요구했다. 단위 자원 추산과 시간 제한 없이 실행했다.

**수정**: 표본을 5,000점으로 줄이고 `full_matrices=False`와 `timeout`을 썼다. 재실행은 수 초 안에 끝났다. 카메라와 p620 문제는 아니었다.

**교훈**: 점군 평면 맞춤의 SVD는 항상 `full_matrices=False`로 쓴다. 분석 스크립트에도 시간 제한을 둔다.
