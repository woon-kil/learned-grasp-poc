# G0d 윗면 마커 사전 시험 계약 2

작성: 2026-11-09 23:47 KST. **새 사진을 찍기 전 고정이다.** 쓰기 0건 시험이다. 플랜 `docs/261109-2129-G0d-재설계-플랜.md` v7의 수치를 정한다. 도구 `scripts/marker_precheck2.py`.

앞선 계약(`docs/261109-2216-G0d-사전시험-계약.md`)의 불합격은 그대로 남는다. 그 사진은 기준을 옮겨 재채점하지 않는다. 판정은 이 계약의 새 사진으로만 한다.

## 왜 다시 하나

앞선 시험에서 보드 마커 id 1이 블록에 가려 값이 비었고, 실제 J1 90 r5 이상의 사진에서도 가려졌다(`docs/261109-2340-G0d-보드마커-가림-이슈보고서.md`). p620 OpenCV 4.5.4는 같은 사진에서 윗면 마커를 놓쳤다. 그래서 다음을 바꾼다.

| 항목 | 앞선 계약 | 이 계약 |
| --- | --- | --- |
| 위치 기준 | 보드 마커 id 1 | 바깥쪽 `DICT_4X4_50` id 0, 1, 3 중심의 평균. 셋 다 있어야 한다 |
| 각도 | id 1과 id 7이 함께 있어야 값이 남 | id 7만으로 계산, 단 기록 조건은 위치와 같다 |
| 분석 경로 | Mac, 버전 미고정 | Mac, `opencv-contrib-python-headless==5.0.0.93` 고정. 실행기도 이 경로만 쓴다 |
| 자리 | 눈대중 세 곳 | 실제 가림 사진을 본뜬 세 곳 |

## 준비

앞선 시험의 블록(윗면 마커 부착)을 그대로 쓴다. 인쇄 실측은 50 mm 선 50 mm, 마커 한 변 25.39 mm(사용자)다.

## 자리

블록의 긴 변은 베이스에서 앞쪽(YAHBOOM 글자 쪽)을 향하고, 중심선이 보드 마커 가운데를 지난다. J1 90, J5 90에서 놓인 방향을 본뜬다. 자리는 눈대중이고 셀 위치를 재현한다고 주장하지 않는다.

| 자리 | 놓는 법 | 본뜨는 것 |
| --- | --- | --- |
| P1 | 앞쪽 끝면과 보드 마커의 베이스 쪽 가장자리 사이가 약 1 cm | 보드 마커가 보이던 쪽(r3 이하) |
| P2 | 앞쪽 끝면이 보드 마커의 베이스 쪽 가장자리에 닿음 | r5 사진 |
| P3 | 보드 마커가 위에서 전혀 보이지 않게 덮음 | r8 사진의 가림 |

돌림은 뒤쪽 끝면 가운데를 두고 앞쪽 끝만 민다. 한 방향 약 1 cm(윗면 60.33 mm에서 계산 약 9.4°), 이어서 반대쪽으로 약 2 cm. 눈대중이다. P2·P3는 이어서 밀림, 치움 사진을 찍는다.

플랜의 ROI 경계 잔류 시험으로 세 자리를 더 찍는다. 빈 보드 사진에 두 ROI를 그려 보니 **노란 화소 ROI(u 585~825, v 190~395) 밖에 종이가 남고**, 분홍 표시 반대쪽 아래 모서리에 블록이 들어갈 만한 띠가 있다. 모두 블록이 종이 위에 남은 배치다.

| 자리 | 놓는 법 |
| --- | --- |
| E1 | 분홍 표시 반대쪽 가장자리와 YAHBOOM 글자 쪽 가장자리가 만나는 종이 모서리에 붙임 |
| E2 | 분홍 표시 쪽 종이 가장자리에 붙임 |
| E3 | YAHBOOM 글자 쪽 종이 가장자리에 붙임 |

좌우 대신 분홍 표시와 글자를 기준으로 쓴다. 사진 좌우와 사람 시점이 달라 혼동되기 때문이다.

합 **16단계, 67장**. 자리마다 정지 10장, 돌림 각 5장, P2·P3 밀림·치움 각 1장, E1~E3 각 1장.

## 시험 유효 조건 (성능 판정보다 먼저)

P1 정지에서 보드 마커 id 1이 **≥ 9/10** 잡히고, P3 정지에서 **≤ 1/10** 잡혀야 한다. 미검출만으로 물리적 가림을 입증하지 않으므로 두 확인을 더 요구한다. (1) P3 정지 촬영 직전 사용자가 마커가 안 보이는지 보고 `y`를 입력해야 찍히고 `shoot_log.json`에 남는다. 찍기 전이라 다시 놓아도 재촬영이 아니다. (2) `fetch` 뒤 `analyze` 전에 Claude가 P3 정지 사진을 보고 카메라 시점에서 마커가 덮였는지 결정해 결과 문서에 적고 **커밋한다.** 그다음 그 값을 `--p3-photo-covered`로 넘긴다. 기록이 없거나 `no`면 무효다. 촬영은 p620 경로가 이미 있으면 시작하지 않고, 세션 ID와 완결 표시를 남긴다. 완결되지 않은 기록은 분석을 거부한다.

**무효면 성능을 계산하지 않고 이 계약을 끝낸다.** 다시 찍기는 없다. 다음은 새 계약이다. 도구는 무효일 때 `pass: null`만 낸다.

## 합격 기준

한 장의 「검출」은 윗면 id 7과 바깥쪽 id 0, 1, 3이 **모두** 잡힌 경우다. 아래 전부를 세 자리에서 만족해야 합격이다.

| 시험 | 기준 |
| --- | --- |
| 정지 검출 | 자리마다 **≥ 9/10** |
| 돌림 검출 | 자리·방향마다 **≥ 4/5** |
| 방향 구분 | 정지 평균과의 `image_angle` 차이 **≥ max(5°, 정지 std × 3)** |
| 두 방향 | 두 돌림의 부호가 **서로 반대** |
| 위치 구분 | 돌림 평균 위치와 정지 평균 위치의 거리 **≥ max(2화소, 정지 2차원 RMS 거리 × 3)** |
| 카메라 | **67장 전부**에서 바깥쪽 마커 셋이 잡히고, 각각 자기 중앙값에서 **≤ 2화소** |
| 거짓 성공 (P2·P3) | 첫 정지 사진 대비 나머지 정지 9장, 돌림 10장, 밀림 1장, 합 **20장씩**의 자동 판정이 **하나라도 성공이면 G0d 진입 금지** |
| 경계 잔류 (E1~E3) | P2 첫 정지 사진 대비 자동 판정이 **하나라도 성공이면 G0d 진입 금지** |
| 제거 (P2·P3) | 치운 사진은 자동 판정 **성공**. 실패면 거짓 실패로 G0d 진입 금지 |

**측정과 판정은 따로 합격한다.** 위 표의 정지 검출부터 카메라까지가 측정(`measure_pass`), 거짓 성공, 경계 잔류, 제거가 판정(`judge_pass`)이다. 판정이 미달이어도 측정 합격은 유효하다. 그 경우 G0d에는 들어가지 않고 판정값을 플랜으로 재계획한 뒤 **판정 부분만** 새 계약과 새 사진으로 본다. 변경이 영향을 주는 게이트는 그 플랜에서 다시 검증한다. 카메라, 마커, 배치, 측정 코드가 바뀌면 측정도 다시 본다. 판정 실패와 전체 미통과는 기록에 그대로 남긴다. 이 분리는 촬영 전에 정했다.

**경계 자리 유효 조건**: E1~E3는 촬영 직전 사용자가 블록 전체가 종이 위이고 지정 가장자리에 닿았는지 보고 `y`를 입력해야 찍히고 `shoot_log.json`에 남는다. 찍기 전이라 다시 놓아도 재촬영이 아니다. 기록이 셋 다 `y`가 아니면 `judge_pass`는 `null`이고 다시 찍지 않고 새 계약으로 간다. **찍은 뒤 사진을 보고 유효 여부를 고르지 않는다.** 결과를 계산하는 쪽이 무효와 실패를 고르면 실패를 무효로 돌릴 수 있기 때문이다.

판정값은 변화 ≥ 0.02, 노란 화소 ≤ 100으로 고정이다. 미달이면 원인을 기록하고 새 플랜으로 간다. 같은 계약으로 다시 찍어 통과시키지 않는다. 앞선 계약의 거짓 성공·제거 결과(0/10, 3/3)는 A·B·C 자리의 값으로만 남기고 P2·P3로 옮기지 않는다.

**앞선 계약과 다른 수치**(결과를 본 뒤 추가했고 판정은 새 사진으로만 한다): 돌림 ≥ 4/5, 두 방향, 위치 구분, 카메라, 유효 조건. 판정을 **완화하는 항목은 없다.** 위치 기준 교체는 앞선 불합격 원인을 없애는 변경이다. 카메라 2화소는 기존 사진 207장의 최대 0.90화소를 보고 정한 **운영 한도**다. 위치 2화소와 함께 검증된 물리 한도가 아니다.

## 합격이 뜻하는 것

**검출, 방향 변화, 눈에 띄는 위치 변화를 고정 카메라에서 구분할 수 있다**는 뜻이다. 눈대중 돌림의 크기라 mm·도 정확도와 배치 필터의 충분성은 말하지 않는다. 필터의 값은 `G0d-0` 자연 흩어짐에서 정하고 플랜의 한계를 그대로 적용한다.

## 이 시험이 말하지 않는 것

- 손으로 놓은 블록이다. 팔이 놓은 배치, 실제 r1·r4·r7의 검출, 집기, 파지 영향은 `G0d-0`에서 본다.
- 조명 변화는 없다. `G0d-0` 묶음 경계 사진에서 본다.
- 돌림은 눈대중이라 각도 정확도를 재지 않는다. 9.4°는 계산값이다.
- 측정값은 평행 이동만 보정한다. 카메라 회전·배율 변화는 보정하지 않고 카메라 기준으로 막는다.

## 검증 근거

아래는 **판정이 아니라 사전 탐색이다.** 후보를 고른 근거이고 합격 근거로 쓰지 않는다. 앞선 계약 사진 67장(블록 있는 사진 64장), 같은 스크립트 대조다.

```text

Mac:  cv2 5.0.0  67 all3 67 id7 64

두 경로 공통 검출분: id7 위치차 최대 0.524 각도차 최대 1.15 기준 위치차 최대 0.354
```

바깥쪽 마커 기존 사진 207장(`marker-top` 67, G0b 60, G0c 60, G0b-9 20) 전부 세 개 검출, 위치 std 최대 0.29화소. 사진 가져오기 3회 0.32, 0.17, 0.17초, 검출 3회 약 0.03~0.04초(Mac).

바깥쪽 마커가 중앙값에서 벗어난 최대 거리, 같은 207장이다(5.0.0.93).


도구 동작 확인이다. 앞선 사진을 이름만 바꿔 연결했고 **판정이 아니다.** 무효 경로, 버전 거부, 전체 경로를 봤다. 전체 경로의 P3는 가림 사진을 정지로, 같은 방향 사진을 두 돌림으로 일부러 연결해 `opposite_ok`가 걸러지는지 봤다.

```text

버전: 판정 중단: OpenCV 4.10.0.84, 계약은 5.0.0.93
전체: {'valid': True, 'pass': False, 'board_tag': {'P1': '10/10', 'P2': '10/10', 'P3': '0/10'}, 'outer_max_px': {'0': 0.354, '1': 0.707, '3': 0.354}}
```

경계 자리와 측정·판정 분리 뒤 다시 돌린 값이다. 역시 판정이 아니다. E1~E3에는 앞선 `edge` 사진을 연결했고 표시한 배치의 사진이 아니다.
