# 사람 개입 최소화 측정 정책 플랜 (초안, 승인 요청)

작성: 2026-11-11 KST. **승인 전이다. 팔에 명령을 보내지 않았고 코드도 바꾸지 않았다.** 계기: P1에서 사용자가 「계속 측정 좌표가 맴도는 것 같다」, 「이 테스트는 여기까지, 다음부터 측정은 사람 개입 최소화 정책으로」라고 지시했다. P1 결과: `docs/261111-1128-P1-조기-마감-결과.md`.

## 1. 문제 (P1에서 실제로 든 사람 비용)

| 항목 | P1 실측 | 비고 |
| --- | --- | --- |
| 시도당 사용자 메시지 | 놓았다, 확인, 치웠다 최소 3개 | 정렬이 틀리면 놓았다가 2~5개 더 |
| 정렬 왕복 | p1-10 5회, p1-15·16·17 3~4회 | ψ ≤ 5° 게이트를 손으로 맞춤 |
| 시도당 시간 | 약 5~10분(정렬 포함) | 20시도 전체는 약 2~3시간 예상이었고 15시도에서 마감 |
| 안내 오류 위험 | 회전 방향을 거꾸로 안내한 사례 1회(p1-15) | 사람이 맞추는 한 계속 위험 |

사람 배치·회수·정렬이 시도 수에 비례해 든다. 표본을 늘릴수록(측정 40, 240시도) 선형으로 커져 실질적으로 반복 측정이 불가능하다.

## 2. 정책 (제안, 승인 대상)

1. **블록은 팔이 놓고 팔이 되돌린다.** 사람은 시작 때 블록을 한 번 적재한다. 기존 G0d 실행기가 이미 이 구조다(`src/learned_grasp/tolerance.py` 머리 설명: `P`에 놓고 park 사진, `P+δ` hover에서 집기, 성공이면 `P+δ`에 놓고 `P`에서 다시 집어 복귀). 사람 배치·정렬·치우기를 시도에서 뺀다.
2. **측정은 성분으로 나눈다.** 사람이 놓은 임의 자리 전체를 시험하는 대신 (a) 개루프 성공 창, (b) L1 오차, (c) L2 반올림을 따로 재고 합성한다. 아래 3절.
3. **사진 판정·배치 확인은 자동 게이트**로 한다(마커 검출 실패, 방향·위치 범위 밖이면 쓰기 없이 정지). 채팅으로 「놓았다」를 받지 않는다.
4. **정지는 묶음 단위 + 이상 시.** 묶음(쉼 묶음 `CLOSE_BATCH`=10) 사이에서만 사람에게 돌아온다. 묶음 중 이상(판정 실패, 검출 실패, 안전 위반)은 자동 정지하고 사람 답을 받는다. 기존 G0d 실패 경로를 그대로 쓴다.
5. **전원 차단 담당은 그대로 사용자이고 안전 규칙은 줄이지 않는다.** 팔이 움직이는 동안 손을 넣지 않는다.

## 3. 측정 설계

### 3.1 주 시험: 연쇄 종단 시험 (사용자 제안 채택)

사용자가 P1 중에 제안했다: 집은 뒤 **다음 시험 좌표에 내려놓는다.** 초안에서는 L2 반올림이 가려진다는 이유로 제외했으나, 자료로 보면 그 이유가 약하다. `docs/261111-0918-명령-셀-블록-영상-위치-맵-분석.md`는 팔이 같은 셀에 놓은 블록의 영상 위치가 **횡방향 1σ 2.8 mm, 반경 3.2 mm** 흩어진다고 했다(G0b·G0c·G0b-9, 팔이 명령 자세로 놓은 블록). 팔이 격자점에 놓아도 실제 블록 위치는 연속값으로 흩어지므로 `round(L1(실제 위치))`의 반올림 오차(J1 ±0.5° ≈ ±1.3 mm)는 정상적으로 생긴다. 즉 **연쇄 시험은 L1과 L2를 모두 통과한다. 다만 사람이 놓는 시험보다 쉬운 시험이다**(L1 맵이 팔이 놓은 블록으로 맞춰졌고, 놓은 자리를 그대로 고르면 재생에 가깝다). 합격 판정은 「집는 자리 ≠ 놓은 자리」를 따로 보고한다(`docs/*연쇄-시험-구현과-L2-반올림-계산-결과.md` 2.2).

한 시도: ① park에서 Gemini 사진 → L1이 (r_index, J1) 계산, ② 그 자리를 집는다(`g0_runner._pick`), ③ park로 와서 **시드로 정한 다음 자리 B**에 놓는다(`g0_runner._place`: hover → grasp → 개방 → hover → park), ④ park 사진이 다음 시도의 입력. 사람은 시작 적재, 매 하강 전 확인(집기·내려놓기 각 1회), 이상 시 회수뿐이다.

- **새 이동 경로가 필요 없다.** `_pick`은 hover에서 끝나고 park를 거쳐 `_place`로 가는 순서는 G0d가 이미 쓰는 호출 묶음이다(`g0_runner.py` 188~201행, `tolerance.py` 머리 설명 「블록을 쥔 채 P에 놓고」, 「P+δ에 놓고 P에서 다시 집는다」). 게이트 변경은 쓰지 않는다. 구현 전 `SafeArm`/`SafetyGate`가 pick 후 다른 셀 place를 허용하는지 시험(Fake)으로 확인한다.
- **자리 B는 사람이 놓는 것과 달리 항상 격자점이다.** 다양한 연속 위치는 팔의 놓기 흩어짐(약 3 mm)에서만 나온다. 이 한계 때문에 아래 3.3 합성이 필요하다.
- **ψ**: 놓을 때 손 yaw가 J1을 따라가므로 블록 긴 변이 반경선에 거의 나란하다. 임의 ψ는 시험하지 않는다(P1도 ψ ≤ 5°만 시험했다). ψ는 3.2(a)의 변형으로 따로 잰다.
- **정지 조건**: 판정 실패, L1이 구역 밖·방향 5° 초과 거절, 마커 검출 실패, 서보 6 판독 > 151. 자동 정지 후 사람 답을 받는다(G0d 실패 경로).

### 3.2 보조 측정 (성분)

| 성분 | 질문 | 사람 없이 재는 법 | 현재 구현 |
| --- | --- | --- | --- |
| (a) 개루프 성공 창 | 명령이 블록 위치에서 얼마나 벗어나도 집히는가(횡방향·반경·ψ) | G0d `tolerance`: `P` 놓기 → `P+δ` 집기 → 복귀. 횡방향 단계가 ±1°뿐이라 **±2°, ±3°를 더한다**(`PROJECT-STATUS.md` 개루프 성공 창 항목). 손 yaw 오프셋은 ψ 변형 포함 여부를 Plan v2에서 정한다 | 실행기 구현, 실기 미실행 |
| (b) L1 종단 일치 | L1이 고른 (r_index, J1)이 **실제로 집힌 자리인가** | 정답 위치가 없다(Gemini 측정뿐, 놓기 흩어짐 약 3 mm와 L1 오차가 섞임). 따라서 (b)는 L1 오차를 따로 재지 않는다. **집기 성공 여부를 진실로 삼는 종단 시험(3.1)이 (b)를 대신한다.** | 3.1의 시험 |
| (c) L2 반올림 | 정수 J1·표 행 반올림 오차 | 계산(쓰기 0): L1 연속값과 반올림값의 차 분포 | H5 시뮬레이션 있음 |

### 3.3 합성

(a)의 창 곡선에 (b)·(c)의 오차 분포를 올려 예측 성공률을 내고, 3.1 연쇄 시험의 실측 성공률과 비교한다. 예측과 실측이 어긋나면 분리하지 못한 오차 원인(놓기 흩어짐 대 L1 오차)이 남는다고 보고한다.

## 4. 사용자 결정 (2026-11-11, CH-0 직후 갱신)

**갱신**: 사용자가 「안전 확인은 최초 블록 집을 때만 필요하고 중간에는 불필요, 위험하면 내가 전원 차단」으로 바꿨다. 아래 원래 결정보다 우선한다. 구현·근거는 `docs/*연쇄-시험-구현과-L2-반올림-계산-결과.md` 2.4.

(원래 결정)

**하강 전 「확인」은 사용자가 직접 한다**(사용자: 「하강 확인은 내가 할께」). 확인 단계는 줄이지 않고 하강마다 유지한다. 전달 수단은 아직 정하지 않았다: 채팅 「확인」이면 시도당 사람 접점이 1개 남고, 전원 차단 위치에서 닿는 터미널 Enter 도구면 채팅 왕복이 없다(G0d 플랜 174행의 방식). Plan v2에서 구현 비용을 보고 정하고, 그때까지는 채팅 「확인」을 기본으로 가정한다. 기술 사항(확장 범위·건수·ψ 변형·계산 순서)은 사용자에게 묻지 않고 Plan v2에서 정한다.

## 5. 진행 순서 (승인 후)

1. (c)는 **쓰기 0**이다. 기존 사진(G0b·G0c 70장)과 L1 맵으로 먼저 계산한다. P1 15시도의 측정(`data/p1/placed-*.png`)과 성공 기록은 3.3 합성의 비교 자료로 쓴다(정답 위치가 없으므로 L1 오차는 못 재고, 성공 여부만 대조).
2. G0d `natural-spread`(G0d-0, 쓰기 있음)는 기존 플랜대로 먼저 실행한다. 이 결과가 `tolerance`의 선행 조건이다(`run_g0d`가 요구).
3. 하강 확인 방식(4절) 결정 뒤 해당 도구 구현·시험. 연쇄 실행기(`run_chain`)는 `run_p1` 위에 `_place`를 붙여 만들고 Fake 시험으로 pick 후 다른 셀 place가 게이트를 통과하는지 먼저 확인한다.
4. 3.1 연쇄 시험 1단 sanity(2시도, 1 쌍)로 쓰기 수·주기·메모리 없음 확인 → `단위 × 건수` 추산 → 전체 승인 요청. 그다음 (a) `tolerance` 1단 sanity.

## 6. 하지 않는 것

P1 20시도 완성, 판정 규칙 변경, 안전 게이트 완화(4절 외). 사람이 놓는 시험은 하지 않는다. 연쇄 시험의 임의 ψ 시험은 하지 않는다.

## 8. 사람 접점 (정책 충족 확인)

시도 10회 기준: P1 = 사용자 메시지 약 30~50개(놓았다·확인·치웠다 + 정렬 왕복), 연쇄 시험 (A)·(B) = 시작 적재 1회 + 묶음 이상 시 응답(정상 시 0), (A)는 하강마다 Enter 입력이 있으나 채팅 왕복은 아니다. 하강 확인을 사용자가 직접 하므로 채팅 수단이면 시도당 1개(10회당 10개), 터미널 Enter 수단이면 채팅 0개. 정책 목표는 **시도당 사용자 메시지 0**이다.
