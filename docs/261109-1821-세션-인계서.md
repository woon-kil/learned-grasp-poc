- **시험 범위는 실제 운영 경로까지여야 한다.** `hover` 유지는 `park` 운반을 대신하지 못했다. 빈 손 드라이런은 하중 조건을 대신하지 못했다.

- **닫으면 손끝이 나온다**(구조적). 블록 없는 경로의 닫기 값을 올리면 손끝이 더 내려온다.

- **Codex 정체**: 입증할 수 없는 주장(3 mm 여유)을 내걸면 방법을 바꿔도 BLOCKING이 계속 나온다. 주장을 빼는 쪽이 정직하다. 다만 마지막 검토는 내 요청 문구가 판정을 유도한 면이 있다.
- **비율 차이 기록**: 22.5 mm 계산 겹침 18~23 mm 대 관찰 상단 1/3의 차이는 여전히 풀리지 않았다.

## 운영 방법

```bash
uv run pytest -q
bash scripts/safe_push.sh                # 푸시는 이것으로만
bash scripts/deploy_jetson.sh            # 서버 파일 복사, 실행 안 함
uv run python -m learned_grasp.session read --session runs/<세션>/approval.json
uv run python -m learned_grasp.session dryrun --session runs/<세션>/approval.json --start-confirmed
uv run python -m learned_grasp.session carry-test --session runs/<세션>/approval.json --attempt N --hold-sec 5 --start-confirmed
uv run python -m learned_grasp.session replay --session runs/<세션>/approval.json --sheet <시험표> --mode stored --start-confirmed
uv run python -m learned_grasp.g0_runner summary --sheet <시험표> --ledger runs/<세션>/replay-stored.jsonl
```

- **쓰기 전 확인**: 승인 파일(`approved_by: user`), 시작 조회, 사진(`ssh p620 'cd ~/projects/learned-grasp-poc && bash scripts/p620_camera.sh capture "$PWD/runs/<세션>/before"'`). 사진 확인으로 블록이 남아 있는 것을 잡은 적이 있다.
- **적재 대기**: 사용자가 「적재 완료」라고 하면 출력에 `need_block`이 있는지 본 뒤 `touch runs/<세션>/block_ready`. `session ready`는 잠금 결함으로 쓰지 않는다.
- **완료 판단**: 사용자의 「이상 없음」이 프로그램 종료 전에 올 수 있다. 다음 단계 전에 실제 종료를 확인한다.
- **긴 실행**: 백그라운드로 돌리고 판정값과 `need_block`을 감시한다. 시도별 값이 출력된다.
- **p620 사본**: `scripts/gemini_serve*.py`는 scp 사본이다. 현재 일치한다.
- **사진**은 `runs/`에만 둔다. 개인 공간이 보여 커밋하지 않는다.
