# P2 사람 배치 J5 정렬 시험 + R1 반경 허용 측정 플랜 (v2, 승인 요청)

작성: 2026-11-11 KST, v2는 같은 날(advisor 지적 반영). 사용자 지시: 「사람이 놓는 블록으로 J5 정렬을 검증하는 시험」과 「반경 허용 측정이나 J5 극단을 쓰는 시험」 둘 다 진행. **승인 전이다. 팔에 명령을 보내지 않았고 코드도 바꾸지 않았다.** 앞선 결과: `docs/*CH-3-J5-정렬-연쇄-40시도-결과.md`(38/40, 한계 3절), `docs/*J5-블록-방향-정렬-분석과-계획.md`. 사람 개입 최소화 정책(메모리 `minimize-human-in-measurement`)을 적용한다.

## 1. 두 시험이 답하는 질문

| 시험 | 질문 | CH-3이 못 답한 이유 |
| --- | --- | --- |
| **P2** 사람이 놓은 블록 + J5 정렬 | 사람이 **임의 방향**으로 놓은 블록을 L1(위치) + J5 정렬(방향)만으로 집는가. J5 극단(60~120 끝)에서도 손 yaw 모델이 맞는가 | CH-3은 팔이 놓은 블록만 집었다(쉬운 시험). J5는 78~98만 썼다. J5 60·120 자체는 G0b·G0c에서 실기로 쓴 적이 있으나(팔이 놓은 블록) 정렬 모델을 극단에서 쓴 적은 없다 |
| **R1** 반경 허용 | 손이 블록 중심에서 반경 방향으로 얼마나 벗어나도 집히는가(L1 반경 오차 σ 약 4 mm 대비 여유) | 모의는 횡방향만 봤다. 반경 허용은 측정한 적이 없다 |

J5 극단은 P2가 겸한다. 별도 J5 시험은 두지 않는다.

## 2. P2 설계

- **블록 놓기(사람)**: 구역(J1 72~108, r 128~160 mm: P1에서 r 125 이하는 구역 밖 거절 2건)에 **방향은 자유롭게** 눕혀 놓는다. 정렬 왕복이 없다. 목표 20자리·방향을 시드로 뽑아 SVG로 보이되 **L1에는 놓은 뒤 측정한 값을 넣는다**(P1과 같은 규칙).
- **목표는 J5로 뽑는다**(advisor 지적: d로 뽑으면 셀마다 d0이 −3~+8°로 달라 J5가 범위 밖이 되는 일이 많다). 목표 J5를 62~118에서 층화 추출(극단 구간 62~70, 110~118을 각 4개 이상 포함)하고, 자리마다 목표 방향 d = `hand_d(J5, J1, r_index)`를 역산한다. 정렬 뒤 J5가 범위 밖(60~120)이면 그 시도는 세지 않고 새 자리로 바꾼다(최대 1회 재배치).
- **시도**: `plan_aligned`로 (r_index, J1, J5) → `run_p1` 경로(park → hover(확인) → grasp → 닫기 → hover → park 5초 → 같은 자리에 도로 놓기) → 자동 판정(관찰기 그리고 서보 6 판독 ≤ 151). 사람은 시도마다 「놓았다」 한 번(도로 놓은 블록을 집어 새 자리에 놓는 것이 치우기).
- **비틀림 측정(P2의 핵심 지표)**: 정렬 후 실제 손-블록 어긋남은 CH-3에서 재지 못했다. 집기 **전** 블록 각도와 도로 놓은 **뒤** 블록 각도(같은 자세·같은 J5)의 차가 닫는 동안의 비틀림이고 손-블록 어긋남의 직접 척도다. 이를 위해 `run_p1`에 **도로 놓은 뒤 park에서 쓰기 없는 사진 1장**을 추가한다(지금은 없고 다음 사진은 사용자가 블록을 옮긴 뒤다). 보고: 비틀림 대 |J5−90|(≤10°, 10~20°, 20~35°)별 분포 = 극단에서 손 yaw 모델이 맞는지의 진단.
- **하강 확인**: 처음 한 번 + **J5 편차 |J5−90|가 이전 확인 최대보다 10° 이상 커질 때마다**(약 10°, 20°, 30° 부근 각 한 번). 이유는 정렬 모델의 극단 불확실성이다(J5 60·120 자체는 쓴 적 있음). 그 뒤는 전원 차단 감독.
- **판정(사전 고정)**: 20시도 합격 ≥ 18/20(P1과 같은 규칙, 방향이 자유라 더 어려운 시험), 불합격 ≤ 15/20, 16~17이면 20시도를 더해 40시도(합격 ≥ 36/40). 모든 실패는 원인(밀림, 내려앉음, 낙하, J5 극단)·J5·방향·비틀림을 함께 기록한다.
- **사람 접점**: 시도당 사용자 메시지 1개(「놓았다」). 20시도 약 40분, 쓰기 약 11회 × 20 = 220(상한 260).

## 3. R1 설계 (사람 개입 0, 연쇄)

연쇄 시험(`run_chain --align`)에 **반경 오프셋**을 붙인다. 집는 행을 L1이 정한 행에서 `Δ`행 옮긴다(손만 반경으로 이동, 블록은 그대로).

- **오프셋 `Δ ∈ {−3, 0, +3}`행을 각 10번, 30시도**(advisor 지적 반영해 축소). 표 행 간격은 4.0~6.0 mm(`r` 119.8, 124.0, 129.7, 134.1, 139.7, 144.1, 149.6, 155.1, 159.1, 165.1)라 ±3행은 약 −15, +17 mm다. 순서는 시드 섞기.
- **놓을 자리는 행 3~6만**으로 만든다(`config/r1_cells.json`, 시드). 집는 행 = L1 행(3~6 부근) + Δ이므로 0~9 안이다. 표 끝 자르기가 없다. 실제 오프셋은 기록한다.
- **오프셋을 쥔 채 놓기**: Δ행 어긋나게 쥔 블록은 손 중심에서 −Δ행 어긋나 있다(블록 중심 = 손 중심 − Δ). 그래서 **놓는 손 행을 `N + Δ`**(N = 목록의 공칭 행)로 해 블록이 공칭 자리 근처에 놓이게 한다. 이 부호는 sanity에서 놓인 뒤 사진으로 확인한다.
- **J5는 실제 행으로 다시 계산**한다: 집기 J5 = `j5_for(d, J1, 집는 행)`, 놓기 J5 = `place_j5(J1, 놓는 행)`. 모델의 행 계수(c = 1.21°/행)가 Δ = ±3행에서 약 ±3.6° 손 yaw를 바꾸므로 보정하지 않으면 반경 효과에 yaw 오차가 섞인다.
- **실패해도 이어 간다(R1 전용, 사전 고정)**: 실패 찾기가 목적인데 지금 규칙은 첫 실패에서 멈춘다. R1에서만 **다음 세 조건이 모두 참이면 이어 간다**: ① 닫은 뒤 서보 6 판독이 빈 손(154 근처, 즉 > 151)이다 ② 다음 사진에서 블록이 구역 안에 있다 ③ L1이 수락한다. 다음 중 하나면 멈춘다: 블록을 못 찾음, 서보 판독이 쥔 값인데 관찰기 실패(오판정 의심), 안전 게이트 위반, 구역 밖. Fake 시험으로 확인한다.
- **오프셋은 L1 추정 대비**다. 블록의 실제 중심 대비는 L1 반경 오차(σ 약 4 mm)가 섞여 곡선이 흐려진다. 한계로 적는다.
- **해석을 미리 고정**: 블록은 반경 방향 길이 60 mm이고 손가락이 폭을 가로질러 닫히므로 ±15~17 mm에서도 성공이 예상된다. 그 결과 「반경 허용 ≥ ±15 mm(L1 반경 σ 4 mm의 3배 이상)」로 읽는다. 어느 쪽 끝에서 성공률이 0.9 아래로 내려가면 그 오프셋이 반경 허용의 상한이다.
- 판정 없음(측정). 보고: `Δ`별 성공/시도, 실패 모양(밀림, 반쪽 집기), 허용 추정과 한계. 오프셋 하강 확인: 처음 한 번 + 처음 |Δ| = 3 한 번 + 처음 오프셋 놓기 한 번(손 행이 블록과 어긋난 채 내려놓기). 그 뒤는 전원 차단 감독.
- **쉼**: 닫기 10번마다 **10분**(CH-3의 5분은 부족했다), 30시도 약 25분 + 쉼 2번 20분 = 약 45분. 쓰기 약 11 × 30 = 330(상한 360).

## 3.1 구현 후 보강 (advisor 2차 지적, 같은 날)

- **빈 손 실패는 grasp 높이에 다시 내려가지 않는다**: 서보 6 판독이 빈 손(> 151)이면 hover → hover에서 열기 → park로 돌아온다(닫힌 손끝은 열린 손보다 약 13 mm 낮아 놓친 블록 위에 내려앉을 수 있다. G0d D4: 실패 뒤 자동 동작 없음). 쥔 값인데 관찰기 실패(오판정 의심)는 기존대로 도로 놓고 멈춘다. `run_chain`·`run_p1` 모두 적용, Fake 시험으로 닫은 뒤 grasp 관절 쓰기가 없음을 확인.
- **오프셋을 쥔 채 놓기의 부호는 가정이 아니라 측정 대상이다**(사전 고정): 놓는 손 행 `N + Δ`가 맞는지는 쥔 블록이 턱 안에서 제자리인지(맞음) 중심으로 미끄러지는지(틀림)에 달려 있다. R1 sanity의 Δ = +3, −3 시도마다 **놓인 블록의 L1 `r_cont`를 공칭 행 N의 r와 비교**한다. N의 ±5 mm 안이면 보정이 맞다. N + Δ 쪽(약 ±15 mm)이면 틀린 것이므로 N에 놓도록 바꾸고 sanity를 다시 한 뒤 본 실행에 간다.
- **P2 극단 목표는 66~70, 110~114로 좁혔다**(범위 끝 60·120 안쪽 3~4°를 피함: 사람의 방향 오차 ±5~10°가 J5로 번져 범위 밖 거절이 되기 쉽다). 극단 목표의 안내는 「방향 ±5°」다. **J5 구간 보고는 실제 J5 기준**이고, 실제 |J5−90| ≥ 20인 시도가 최소 4개 되도록 한다.
- R1 sanity는 새 폴더 `runs/R1-0`(본 실행 30시도에 세지 않음), `--rest-sec 600`, `--count 3`(오프셋 [0, +3, −3]), 확인 약 3번(첫 집기, 처음 |Δ|=3 집기, 처음 오프셋 놓기). 오프셋 하강에서는 손이 블록 길이 방향으로 일부러 어긋나 있고 손가락이 30 mm 폭을 가로지르는지 본다. 손가락이 블록 끝·윗면에 내려앉을 것 같으면 「멈춰」.

## 4. 구현 (승인 후)

1. `run_p1`: `trial["j5"]`를 쓰도록 고치고 `p1-pick --j5`, J5 상승 확인(`confirmed_dev`), 도로 놓은 뒤 park 사진 추가. Fake 시험.
2. `run_chain`: 반경 오프셋 일정(`--offsets`, `--cells`로 r1 자리), 놓기 행 `N + Δ`, 실제 행 기준 J5, 오프셋 상승 확인, 쉼 시간 인자, R1 실패 이어 가기 규칙. Fake 시험.
3. `scripts/p2_targets.py`(J5 층화 20자리·방향 역산, SVG 안내), `scripts/r1_cells.py`(30시도 오프셋 일정과 놓을 자리).
4. 1단 sanity: R1 3시도(Δ = −3, 0, +3 각 1), P2 2시도. 합격은 기계적(J5 쓰기, 확인 동작, 기록, 놓기 부호). 각각 쓰기 약 35·25회, 별도 승인.

## 5. 순서와 부하

R1(사람 접점 없음)을 먼저 하고 P2를 잇는다. 두 시험 사이에 **그리퍼를 30분 이상 쉬게** 한다. 오늘 안에 둘 다 하면 각 승인(23:59 만료)이 같은 날 안에서 쓰인다. 쓰기 합계 약 330 + 220 = 550(상한 360 + 260). 각 실행 전에 단위 sanity로 쓰기·주기를 재고 승인을 요청한다. 부하는 팔 이동·사진뿐이라 메모리·디스크 누적은 없다.

## 6. 하지 않는 것

판정 규칙·문턱 변경, 사후 완화, 사람 배치에서 방향 맞춤 요구, J5 60~120 밖, 횡방향 허용 측정(별도 계획), 관찰기 영역·한계 변경(종이띠 유지).

## 7. 위험

| 위험 | 대응 |
| --- | --- |
| J5 극단에서 손 yaw 모델(J5 60·90·120 세 수준) 비선형 | P2에서 J5 편차별 비틀림·성공을 보고, 어긋나면 모델 한계로 기록 |
