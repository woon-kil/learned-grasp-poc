# DB-8 블록 위치 대 마커 영상 위치(자코비안) — 측정 플랜과 승인 요청 (초안)

작성: 2026-11-10 KST. 실행 전 기록이다. **지금은 승인 전이고 팔에 명령을 보내지 않았다.** 사용자 선택 「1」(블록을 옮겨 영상 위치 변화 보기). 푸시는 측정 후 함께 한다. 앞선 결과: `docs/261110-2113-DB-7-r0-hover-블록마커-결과.md`.

## 1. 목적

L3는 `r_index 0` hover에서 블록 윗면 마커의 **영상 위치(행·열)와 크기**를 보고 블록-손 상대 위치를 보정한다. 그러려면 **블록이 움직일 때 마커가 영상에서 얼마나 움직이는지(화소/mm)** 를 알아야 한다. DB-8은 블록을 정해진 양만큼 옮겨 그 비율을 잰다. 판정 게이트가 아니다.

## 2. 설계

- **자세와 명령**: DB-7과 같다. `session dabai-view --r-index 0 --hover-only --start-confirmed`, `park → hover(r_index 0) → (촬영, 신호) → park`, 회차마다 `write6` 3회, 열린 손, 닫지 않음, `grasp` 없음.
- **회차(블록 이동, 사진 방향은 안내 SVG `data/db8/db8-gap-guide-photo.svg`)**:
  1. 오른쪽(분홍 U 쪽)으로 약 10 mm
  2. 왼쪽으로 약 10 mm
  3. 베이스 쪽(위)으로 약 5 mm
  기준은 DB-7의 블록 자리(블록 방향 긴 변 앞뒤, 마커 위)다. **블록을 사용자 쪽(앞)으로는 밀지 않는다**: 사진을 크게 보니 보드 마커(id 1)가 블록의 사용자 쪽에 거의 닿아 있어(틈 약 0~3 mm) 앞으로 밀면 보드 마커 위로 올라간다. 베이스 쪽 이동은 마커가 영상 아래 끝으로 가서 5 mm로 제한한다.
- **위치 측정**: 사용자가 자로 옮긴 양을 재서 알린다. 좌우 이동은 블록 중심선과 보드 마커 중심선의 차이 e(mm), 베이스 쪽 이동은 블록 끝과 보드 마커 사이 틈 g(mm). **알려 주는 값은 자로 잰 값만 쓰고 기대 화소는 알리지 않는다.**
- **자리 확인**: 블록을 옮긴 뒤 Claude가 Gemini 사진으로 확인한다(보드 마커 가림, 방향, 손끝 금지 구역).
- **안전**: DB-6·DB-7과 같다. `park→hover(r_index 0)` 경로 모델 간격은 블록 자리 위 약 37 mm이고 블록 이동량 ±10 mm 이내에서 변하지 않는다. 팔이 `park`일 때만 블록을 만진다.

## 3. 분석 정의 (실행 전 고정)

- 각 회차 영상에서 블록 마커 id 7을 **기본 검출 파라미터**(빨강 채널)로 검출하고 행·열 범위, 중심 화소, 변 길이, 코너가 영상 안인지를 보고한다.
- DB-7(블록 기준 자리)의 중심 화소와 변 길이를 기준으로 **중심 화소의 변화량(Δ열, Δ행)과 변 길이 변화**를 구한다. 사용자가 잰 이동량(e, g)의 차이(DB-7의 e, g도 함께 잰다)로 나눠 **화소/mm**를 낸다.
- 모델 예측 화소/mm(FK 투영, 검증된 모델)와 **분석 후에** 비교한다. 예측은 사용자에게 알리지 않는다.
- 검출 실패 시 원인을 영상으로 적고 재시도하지 않는다.

## 4. 승인 요청 (회차마다 별도)

| 항목 | 내용 |
| --- | --- |
| 게이트 | `DB-8-1`(오른쪽 10 mm), `DB-8-2`(왼쪽 10 mm), `DB-8-3`(베이스 쪽 5 mm). 판정 게이트가 아니다 |
| 구성 | 6, 표 해시 `4b38b02de6f64ffab638c5672debabbbf17b1711fe2fd881fee78f3008cc387d`, `verified_g0a: true` |
| 명령 | 회차마다 `dabai-view --r-index 0 --hover-only`, `write6` 3회(8000, 5100, 5100 ms), `max_writes` 3 |
| 대기 | 도착 줄 → 프로브 12초 → 신호 → park 복귀. 상한 300초 초과 시 정상 전이로 복귀 |
| 관찰 | 이동 중 접촉(특히 블록과 손끝·DaBai), 이상음, 떨림, 케이블 걸림. 종료 후 조회의 J2가 90에서 얼마나 벗어나는지(DB-7에서 93) |
| 전원 차단 담당 | 사용자. 팔이 움직이는 동안과 대기 중에는 손을 넣지 않는다. 블록은 팔이 park일 때만 만진다 |
| 전원 차단 | 접촉, 낙하, 튐, 이상음, 냄새, 떨림, 케이블 걸림. 스톱 버튼 사용 안 함 |
| 세션 중단 | 조회 불일치, 연결 단절, `None` 재발. 안전 위반은 자동 쓰기 없음 |
| 시작 조건 | Jetson에 다른 `jetson_arm_server`·드라이버 없음, 남은 쓰기가 있는 다른 승인 없음, 시작 전·후 조회, 자리 확인(Gemini) |
| 만료 | 승인한 날 23:59 KST |

사용자에게 받을 것(회차마다): 「승인, e 또는 g ○○ mm(자로 잰 값), 시작 확인, 그리퍼 ○○도」, 끝 온도와 이동 중 관찰. **먼저 현재 자리(DB-7의 블록 자리)의 e와 g도 재서 알려 달라.**

## 5. 하지 않는 것

닫기·집기, `grasp`, 다른 r_index·J1·J5, 표 변경, 새 전이, 새 코드. 블록을 사용자 쪽으로 밀기, 보드 마커·바깥쪽 4X4 마커·Gemini 스탠드 건드리기. 이 결과로 L3 채택을 정하지 않는다.

## 6. 위험

| 위험 | 대응 |
| --- | --- |
| 블록을 옮기다 보드 마커를 가림·건드림 | 앞으로 밀지 않음, 자리 확인 사진, 영상 확인 |
| 베이스 쪽 이동으로 마커가 영상 아래로 잘림 | 5 mm로 제한, 잘리면 그대로 기록(재시도 없음) |
| 사용자 측정 오차(자 ±0.5 mm)로 화소/mm 오차 | 이동량 10 mm이면 약 5%, 결과 한계에 적는다 |
| 종료 후 J2 오차 반복 | 회차마다 종료 후 조회를 기록 |
