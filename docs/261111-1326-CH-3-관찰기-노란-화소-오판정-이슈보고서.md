# CH-3 chain-006 관찰기 「노란 화소」 오판정 이슈 보고서

작성: 2026-11-11 KST. 관련: 세션 `runs/CH-3`(gitignore), 관찰기 `session.py` `make_pick_observer`(영역 `PICK_BOARD_ROI`, 한계 `PICK_YELLOW_MAX` 100), 노란 화소 계산 `scripts/gemini_serve_core.py` `yellow_pixels`.

## 현상

CH-3 연쇄 40시도(J5 정렬)가 6번째 시도에서 멈췄다. 기록 `runs/CH-3/chain.jsonl`:

```
chain-006 실패(물체가 보드에 남은 것으로 판정, 변화 0.0370, 노란 화소 109, 서보 6 판독 149)
```

- 시도 1~5는 성공(집기 5/5). 시도 6은 사전 고정 규칙(관찰기 그리고 서보 6 판독 ≤ 151)에서 **실패**로 기록됐다(공식 집계 5/6).
- 서보 6 판독은 149로 블록을 쥔 값이다(빈 손 154). `chain-006-after` 사진은 보드가 비어 있다(블록은 손에 있음). 즉 **관찰기의 오판정**이다.
- 실패 경로가 작동해 팔이 블록을 pick 자리 (r_index 2, J1 75)에 도로 놓고 멈췄다. 쓰기 61회, 이상 접촉 없음.

## 원인

관찰기의 「노란 화소」 영역 `PICK_BOARD_ROI`의 첫 영역 (585, 825, 150, 395)의 오른쪽 가장자리(x ≥ 789)가 **보드 종이 밖의 탁자 나무**를 포함한다. 노란 화소 109개 중 108개가 x ≥ 789이다(`chain-006-after` 히스토그램 `[1, 0, 0, 0, 0, 108]`, 구간 612~824). 나무는 조명·노출에 따라 노란색 판정을 넘는다. CH-3의 이후 사진에서 **오른쪽 띠(x ≥ 785) 노란 화소**:

```
chain-001-after 0, chain-002-after 71, chain-003-after 9, chain-004-after 63, chain-005-after 11, chain-006-after 108, 현재 park 1
```

한계 100에 근접한 사진이 이미 둘(71, 63)이고 이번에 넘었다. 보드 종이는 움직이지 않았다(보드 마커 id 1 중심이 CH-3 전 사진에서 (691.0~691.5, 291.0~291.75)). 이 영역은 G0b-9 판정 계약에서 고정했는데 당시 사진에는 나무가 노란색으로 잡히지 않았을 수 있다(조명 차이, 미확인).

## 수정

- **판정은 바꾸지 않는다.** chain-006은 사전 규칙에서 실패로 남기고 재채점하지 않는다. 공식 집계와 별도로 「관찰기 오판정(서보 149와 사진이 블록을 쥔 것을 보임)」을 주석으로 남긴다(G0d 플랜: 원 판정과 사람 관찰을 함께 보존). 최종 보고에 공식 집계와 오판정 주석 줄을 합치지 않고 따로 쓴다.
- 관찰기 영역·한계를 시험 도중에 소프트웨어로 바꾸지 않는다(판정 정의 변경이라 계약 4 사진 재검증이 필요하고, J1 104~108 자리에서 오른쪽으로 밀린 블록을 놓칠 위험).
- **물리적 해결**: 보드 종이 오른쪽 가장자리 바깥, 나무가 ROI 안에 들어오는 띠(x 785~825, y 150~395, 바깥 4X4 카드 왼쪽의 나무 두 곳)를 흰 종이띠로 덮는다. 보드 종이·마커 id 1·바깥 4X4 카드는 덮거나 밀지 않는다. 확인: 다시 찍은 사진에서 오른쪽 띠 노란 화소가 0 근처.

## 교훈

- 관찰기 영역은 보드 종이 안으로만 둔다. 영역이 종이 가장자리를 넘으면 조명 변화가 오판정을 만든다. 영역을 만들 때 다른 조명·노출 사진으로 영역 밖 색 화소 수를 검증한다.
- 판정이 자동화돼 사람이 시도마다 보지 않을 때, 오판정은 시도 하나가 아니라 실행 전체를 멈춘다. 한계에 근접한 값(71, 63)이 이미 보였으므로 sanity에서 영역 안 화소 분포를 확인했어야 했다.
