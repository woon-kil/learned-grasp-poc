## 이번에 배운 핵심

- 닫으면 손끝이 약 16~20 mm 돌출한다(사용자 지적, `docs/261109-1257-그리퍼-돌출-계산.md`). 17.5 mm 아래에서 닫지 않는다.
- 개방 간격은 약 37~43 mm로 블록 대비 한쪽 약 3.5~6.5 mm 여유다. 프로젝트의 큰 위험이다(R13).
- 전원 차단 시 팔이 작업대까지 낙하한다. 마지막 수단이다. 재투입 뒤 첫 복귀에서 손끝이 약간 끌렸다.
- Jetson은 별도 어댑터로 동작하는 것으로 보인다. `shutdown` 뒤에는 어댑터를 다시 꽂아야 한다. 이번 재부팅으로 기존 프로젝트의 DaBai 프로세스는 내려간 상태다.
- Gemini는 드라이버 시작 후 약 4초 뒤 노출이 안정된다. 영상이 어두우면 환경 탓 전에 수렴을 본다.
- SDK 조회값이 낙하 후 실제 자세 변화를 따라갔다(J2 58→48, 1회 관찰).

## 운영 방법

```bash
uv run pytest -q
bash scripts/safe_push.sh                # 푸시는 이것으로만
bash scripts/deploy_jetson.sh            # 서버 파일 복사, 실행 안 함
uv run python -m learned_grasp.session read --session runs/<세션>/approval.json
uv run python -m learned_grasp.session grip-test --session runs/<세션>/approval.json --z-mm 22.5 --hold-sec 10 --start-confirmed
```

- 팔을 움직이는 명령은 세션 승인 파일(`runs/<세션>/approval.json`, `approved_by: user`)이 있어야 하고, 범위와 쓰기 수를 먼저 알려 승인받는다.
- 블록 적재 대기 중에는 내려가기 전에 사진으로 손과 블록을 확인한 뒤 `runs/<세션>/block_ready` 파일을 만든다.
- 사진은 개인 공간이 보여 `runs/`에만 두고 커밋하지 않는다.
- 촬영: `ssh p620 'cd ~/projects/learned-grasp-poc && bash scripts/p620_camera.sh capture "$PWD/runs/<세션>/<이름>"'`. p620 쪽 `scripts/`는 scp 사본이라 수정하면 다시 복사한다.

## 알려진 결함

- `session ready` 명령은 실행 중인 세션의 잠금에 걸려 동작하지 않는다. `main`에서 잠금보다 먼저 처리하도록 고친다. 지금은 `block_ready` 파일을 직접 만든다.
- `core.hooksPath` 변경은 권한 분류기가 거부했다. 로컬 훅은 꺼져 있고 `safe_push.sh`가 표준 경로다.
- 구성 2의 `verified_g0a: true`는 17.5 mm 표 기준이다. 높이를 바꾸면 표가 달라진다.
- 플랜의 잔여 항목 M4~M7과 Codex 안전 리뷰 잔여 3건은 `PROJECT-STATUS.md`에 있다.
- 세션 이슈 종합은 개별 이슈 문서(`docs/*이슈보고서.md`, G0a 결과 문서)로 대신했고, 통합 문서는 아직 없다.
