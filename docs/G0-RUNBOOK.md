# G0 실행 절차

플랜 §6·§9의 실행 문서다. 판정 수치는 플랜이 정본이다. 이 문서를 읽는 것은 장치 실행 승인이 아니다.

## 1. 시작 전 조건

아래가 모두 끝나기 전에는 쓰기 명령을 보내지 않는다.

| 항목 | 담당 | 확인 방법 |
| --- | --- | --- |
| 물체 | 완료 | 노란 블록 |
| 카메라 고정 | 사용자 | `docs/261109-1049-물체-카메라-구성-결정.md` §3 위치에 고정, 네 모서리 확인 사진, 기준 이미지 저장 |

## 2. 세션 승인

세션마다 `config/session.example.json` 형식의 파일을 `runs/<세션>/approval.json`에 만든다. 대상, 명령 범위, `max_writes`, 관찰, 중단 조건, 전원 차단 담당, 만료 시각을 적고, 사용자가 승인하면 `approved_by`를 `user`로 한다. 코드는 이 파일 없이는 실장치 드라이버를 만들지 않고, 서버는 쓰기 수가 `max_writes`를 넘으면 세션을 끝낸다. 범위 밖 명령은 새 세션이다.

쓰기 수 계산: G0a 시도당 4회 + 시작 1회. G0b·G0c 시도당 10회, 실패 시 +3회(`hover`, 개방, `park`), 사람 적재 후 +5회, 시작 2회, 정상 종료 시 내려놓기 +5회. 실패·성공이 섞이면 전부 실패보다 많을 수 있으니 최악 경로를 Fake로 계산한다. `max_writes`는 이 합계에 여유를 조금만 둔다.

## 3. 감독자 규칙

- 전원 차단 위치에 손을 두고 상주한다. 자리를 비우면 세션을 끝낸다.
- 예상 밖 움직임, 접촉, 케이블 걸림, 물체 낙하에는 전원을 끊는다. 판단을 기다리지 않는다.
- 전원을 끊으면 팔이 처질 수 있다. 처짐 범위에 손을 넣지 않고 낙하받이를 둔다.
- 소프트웨어 종료는 진행 중인 서보 이동을 멈추지 않는다.
- 보드 스톱 버튼을 눌렀더니 팔이 낙하했다(`G0b-6`). 재개 방법과 토크 상태는 시험하지 않았으므로 전원 차단 대신 쓰지 않는다. 눌렀으면 전원을 껐다 켜고 `session park` 1회로 복귀한다. 이 쓰기는 팔 이동과 그리퍼 개방을 함께 명령한다.

## 4. 게이트별 절차

### G0a 안전

1. 첫 쓰기 전에 사용자가 빈 그리퍼, 시작 자세, `park`까지의 경로를 눈으로 확인하고 답한다(`--start-confirmed`). 프로그램은 시작값을 읽어 첫 이동각이 상한을 넘으면 거부한다. 시작값은 목표로 쓰지 않는다. 첫 이동은 `park`만 허용되고 최소 8초다. 이동 뒤에는 SDK 반환을 목표와 비교해, 어긋나면 다음 쓰기를 막는다. 이 비교는 축 실측이 아니다.
2. 표는 `base_link` z=0을 작업대로 가정한 모델 값이고 `hover`도 이 가정에 의존한다. 첫 접근 전에 베이스와 작업대의 높이 관계, DaBai 본체 여유를 눈으로 확인한다. 작업대에서 충분히 높은 자세부터 단계적으로 내려 실제 높이를 보고, 다르면 `z_grasp_mm`를 고쳐 표를 다시 만든다. 이 높이 탐색은 `session ladder`로 z+15, 5, 0 순서이고 단계당 쓰기 25회(시작 1회 + 6곳×4회)다. 단계마다 사용자 관찰을 `session observe`로 기록해야 다음 단계로 간다. 자세와 명령 수는 세션 승인 범위에 적는다.
3. 표 항목 전체를 J1 양끝·중앙, J5 양끝에서 `park→hover→grasp→hover→park`로 빈 그리퍼 수행한다. 그리퍼를 연 채로 돌기 때문에 닫으면 16~20 mm 나오는 손끝의 작업대 간격은 여기서 확인되지 않는다.
4. 이상을 보고하면 즉시 끝난다. 같은 기록으로는 재개할 수 없다. 연결 단절로 중단된 경우도 같다. 팔 상태를 확인하고, 필요하면 그 조합을 표나 범위에서 뺀 뒤 구성 버전을 올려 새 기록으로 처음부터 다시 한다.
5. 빈 그리퍼, 낮은 자세에서 전원 차단 거동을 1회 기록한다.

통과하면 `verified_g0a: true`와 구성 버전, 표 해시를 기록한다. 표가 바뀌면 G0a를 다시 한다.

### G0b 저장 q 재생

`g0_runner sheet --gate G0b --seed 1`로 시험표를 만들어 저장하고, 실행 전에 커밋한다. 실패 셀을 제외하거나 재시도하지 않는다. 중단된 시도는 분모에 남는다. 물체를 쥐는 동안에는 낙하받이를 쓴다.

집기 성공은 **변화 ≥ `PICK_CHANGE_MIN`이고 보드 안쪽 노란 화소 ≤ `PICK_YELLOW_MAX`**다. 두 값은 시도마다 기록한다. 판정값은 교정 세션 `G0b-9`를 반영해 고정했고(`docs/261109-1957-G0b-9-교정-열-확인-결과.md`), G0d 전에 윗면 마커 블록에 맞춰 다시 정했다(`docs/261110-1008-G0d-판정값-재계획-플랜.md`: 변화 0.01, 노란색 영역 2개의 합). G0b·G0c 기록은 그때 값으로 판정했고 결과를 본 뒤 바꾸거나 이전 기록을 다시 채점하지 않는다.

**열 확인 조건**: G0b는 블록을 쥔 시간이 길고 서보 허용 시간의 공식 근거가 없다. `close_sdk`를 올린 값으로 G0b 유지 패턴을 재현한 열 확인을 별도 플랜으로 통과하기 전에는 G0b에 들어가지 않는다. 이상음, 냄새, 떨림은 전원 차단이다. 전원이 있는 동안 서보를 만지지 않는다(`docs/261109-1555-조임-운반-플랜.md`).

**묶음 진행**: G0b는 시험표 30회를 시험 순서대로 10회씩 3묶음으로 돈다. 세션 폴더는 `runs/G0b/` 하나로 기록과 쓰기 수를 공유하고, 묶음 파일은 `results/G0b/sheet-config6-seed1-batch{1,2,3}.json`이고 판정은 `summary --sheet results/G0b/sheet-config6-seed1.json --ledger runs/G0b/replay-stored.jsonl`, 즉 원본 30회 기준이다. 묶음 사이 5분 이상 쉬고 그리퍼 서보 표면 온도를 잰다. 시작값 +15 ℃ 이상 또는 40 ℃ 이상을 읽으면 즉시 전원 차단이다(운영 한도, 안전 입증 아님). 상세는 `docs/261109-1642-G0b-전-위치-교정-열-확인-플랜.md`다.

**낙하 규칙**: 자동 판정은 보드 밖 낙하를 알 수 없고, 낙하 전에 그 시도가 성공으로 기록될 수 있다. 감독자가 낙하를 1건이라도 관찰하면 즉시 전원을 차단하고, 집계와 무관하게 그 실행은 **미통과**로 기록한 뒤 플랜 §6의 실패 절차를 따른다. `summary`의 `gate_pass`는 성공 수만 보므로 이 규칙이 우선한다. 기록을 고치거나 시도를 제외하지 않는다. 실패 경로의 `hover` 개방은 명령된 동작이라 낙하로 세지 않는다. 보드 위 가장자리로 밀린 경우도 감독자가 보고 결과 문서에 적는다.

**끝과 재개**: 정상 종료하면 마지막 블록을 그 시도의 집기 자세에 내려놓고 `park`로 간다. 예외·쓰기 상한·전원 차단에서는 자동 복구 이동이 없다. 재개는 `park`에서 그리퍼를 열기 때문에 **블록을 쥔 채 재개하지 않는다**. 블록이 손에 남았으면 사람이 받아 빼고 빈 그리퍼를 확인한 뒤(`--start-confirmed`) 별도 승인으로 진행한다.

첫 통과에서 시험표에 있는 표 항목별로 아래를 본다(시드 1 시험표에 항목 3, 7번은 없다). 그리퍼 돌출 때문에 드라이런으로 확인되지 않은 항목이고, 승인 요청의 관찰 칸에 그대로 옮긴다.

- 닫을 때 손끝과 작업대 접촉, 블록을 잡는 높이. 닫은 상태의 관찰은 지금까지 r≈140 mm 한 곳뿐이다.
- 놓을 때 블록 끌림. 열면 손끝이 16~20 mm 올라가는 계산이다.
- 블록을 들고 `hover`와 `park`로 이동할 때 블록 아래면과 손끝의 간격. 지금까지 들어 본 것은 `hover`까지다.
- 집기 실패로 빈 손으로 닫힐 때 손끝 높이. 블록이 있을 때보다 약 2 mm 더 나오는 계산이다.

### G0c 라벨→표 재생

같은 시험표를 `mode=label`로 수행한다. 라벨에서 복원한 명령이 원래와 다르면 즉시 중단한다.

### G0d 허용 오차

정본: `docs/261109-2129-G0d-재설계-플랜.md` v9. 값은 **명령 공간** `tol_cmd_r`, `tol_cmd_lateral`, `tol_cmd_psi`이고 물리 허용 오차가 아니다.

- **준비(쓰기 0건)**: 윗면 마커 id 7 부착, 판정 계약 4 합격(`docs/261110-1034-G0d-판정-계약4-결과.md`). 시험표는 `g0_runner sheet --gate G0d --seed 1 --out results/G0d/sheet.json`으로 만들어 실행 전에 커밋한다. 승인 파일에 `close_limit_s`(닫힘 한도)와 `release_s`(미파지 답 뒤 `hover` 이동·개방 실측 시간)를 넣는다. 기본값은 없다. `max_writes`는 `scripts/g0d_write_budget.py` 값(Fake, 전부 성공 기준 G0d-0 678회·8묶음, G0d 1차 상한 1967회·23묶음, 묶음당 최대 101회)에 여유를 더해 정한다. **쉼 묶음**: 실제 닫기 10회에 닿기 전에 블록을 내려놓고 멈춘다. 열을 확인한 뒤 같은 명령을 다시 실행하면 이어서 한다. 묶음 시작은 사람 적재다.
- **사람 답**: 실행기가 `question.json`을 쓰면 감독자가 전원 차단 위치의 터미널에서 `session answer --session <승인>`으로 답한다. 하강 전 확인은 `y`/`n`, 판정 실패는 `miss`/`held`/`unknown`, 배치 재적재는 `y`/`n`. 마감을 넘긴 답은 받지 않는다. 답을 자동화하지 않는다.
- **`G0d-0`**(`session natural-spread`): 셀 r_index 1·4·7, J1·J5 90. 일반 경로 24회 뒤 경로 비교 18회(셀마다 복귀·일반 교차 3번), 합 42회. 첫 실행 사진에서 바깥쪽 마커 id 0, 1 기준을 `reference.json`으로 고정해 이후 묶음과 G0d 1차가 그대로 쓰고, 배치·판정 사진마다 2화소를 넘으면 추가 쓰기 없이 멈춘다. 적재 직후 같은 셀에서 준비 순환(놓기→판정→P 집기, 시도로 세지 않음)을 한 번 해서 묶음 첫 배치도 일반 경로 다음이 되게 한다. 기준·흩어짐은 spread 단계(셀당 8회) 배치만 쓰고 각도 기준은 원형 평균이다. 결과 `spread.json`: 셀별 기준(일반 경로 다음 배치 중앙값), 흩어짐(편차 최대), `transfer`(복귀 다음 같은 셀 배치가 흩어짐을 넘으면 `unverified`), 집기 성공 사진 노란 화소 최대. **집기 실패 1건 또는 노란 화소 52 초과면 G0d 1차로 가지 않는다.**
- **G0d 1차**(`session tolerance --sheet results/G0d/sheet.json --spread runs/G0d-0/spread.json`): 18변형, 회차마다 시드 고정 교차, 4성공 통과·2실패 미달. 배치 필터는 `spread.json` 값이다. 한 시도: P 놓기→배치 확인→P+δ `hover`에서 하강 전 확인(여기서 시도 ID 소비)→집기→판정→실패면 쓰기 없이 답 대기, 성공이면 P+δ에 도로 놓고 P에서 하강 전 확인 뒤 재집기. 결과 `tolerance.json`.
- **멈춤**: 판정 실패 뒤 `held`·`unknown`·무응답·늦은 답, 복귀 재집기 하강 거부, 카메라 기준 이동은 추가 쓰기 없이 끝난다. 닫힘 한도가 만료되면 모든 쓰기를 막는다. 그리퍼는 닫힌 채 팔이 서 있으니 실행 전에 합의한 절차를 따른다. 받침·전원 차단 기록은 실기 승인 전에 다시 정한다.

### G0e 운영

G0b 기록에서 성공 표본당 시간을 집계한다. 카메라 재연결 1회와 낙하 판별력(그리퍼 판독, 이미지 차이)을 측정한다. 그리퍼 판독이 물체 유무를 구분한다는 것은 아직 가정이다.

## 5. Codex 잔여 항목의 처리

| 항목 | 결정 | 상태 |
| --- | --- | --- |
| B3 G0a 범위 | 표 전체×J1 3×J5 2. 실행 범위는 이 구간으로 제한 | 구현 |
| M4 `tol` 집계 | 셀·부호별로 작은 오프셋부터 연속 ≥4/5인 최대값, 그중 최솟값. 전부 실패면 0 | 구현 |
| M4 비교식 | S1 전에 확정: 위치 오차를 `r`와 횡방향으로 나눠 각 p90을 각 `tol`과 비교하는 안 | 예정 |
| M5 선택 규칙 | G1 전에 확정: A/B는 고정 검증셋의 위치 p90 기준, 5% 이내면 단순한 B | 예정 |
| M6 분할 | G1 전에 확정: 셀 단위, G1 검증 셀은 G2 학습에 넣지 않음 | 예정 |
| M7 모델 명세 | S1 전에 확정: 채널별 정규화, 온도, 출력 차원 | 예정 |

위 "예정" 칸은 제안이고, 확정할 때 해당 단계 실행 전에 커밋한다.
