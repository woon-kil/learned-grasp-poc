# G0 실행 절차

플랜 §6·§9의 실행 문서다. 판정 수치는 플랜이 정본이다. 이 문서를 읽는 것은 장치 실행 승인이 아니다.

## 1. 시작 전 조건

아래가 모두 끝나기 전에는 쓰기 명령을 보내지 않는다.

| 항목 | 담당 | 확인 방법 |
| --- | --- | --- |
| 물체 | 완료 | 노란 블록 |
| 카메라 고정 | 사용자 | `docs/261109-1049-물체-카메라-구성-결정.md` §3 위치에 고정, 네 모서리 확인 사진, 기준 이미지 저장 |
| 접속 정보 | Claude | `.env`에 `LG_JETSON_HOST` |
| Python, `Arm_Lib` 시그니처, import 시 표준출력 오염 여부 | Claude | Jetson 읽기 전용 점검, 쓰기 0건. 출력이 있으면 JSON 프로토콜이 깨져 세션이 끝나므로 서버를 고친다 |
| `arm_driver` 미실행, I2C 점유 없음 | Claude | 프로세스 조회 |
| `park`, 개방·닫기 값, J1·J5 범위 | 사용자와 Claude | 첫 세션에서 관찰로 정해 구성에 기록 |
| 스냅샷 경로 (G0b부터) | Claude | `P620Camera` 구현, 1회 촬영 |

## 2. 세션 승인

세션마다 `config/session.example.json` 형식의 파일을 `runs/<세션>/approval.json`에 만든다. 대상, 명령 범위, `max_writes`, 관찰, 중단 조건, 전원 차단 담당, 만료 시각을 적고, 사용자가 승인하면 `approved_by`를 `user`로 한다. 코드는 이 파일 없이는 실장치 드라이버를 만들지 않고, 서버는 쓰기 수가 `max_writes`를 넘으면 세션을 끝낸다. 범위 밖 명령은 새 세션이다.

쓰기 수 계산: G0a 시도당 4회 + 시작 1회. G0b·G0c 시도당 10회, 실패 시 +1회, 사람 적재 후 +5회, 시작 2회. `max_writes`는 이 합계에 여유를 조금만 둔다.

## 3. 감독자 규칙

- 전원 차단 위치에 손을 두고 상주한다. 자리를 비우면 세션을 끝낸다.
- 예상 밖 움직임, 접촉, 케이블 걸림, 물체 낙하에는 전원을 끊는다. 판단을 기다리지 않는다.
- 전원을 끊으면 팔이 처질 수 있다. 처짐 범위에 손을 넣지 않고 낙하받이를 둔다.
- 소프트웨어 종료는 진행 중인 서보 이동을 멈추지 않는다.

## 4. 게이트별 절차

### G0a 안전

1. 첫 쓰기 전에 사용자가 빈 그리퍼, 시작 자세, `park`까지의 경로를 눈으로 확인하고 답한다(`--start-confirmed`). 프로그램은 시작값을 읽어 첫 이동각이 상한을 넘으면 거부한다. 시작값은 목표로 쓰지 않는다. 첫 이동은 `park`만 허용되고 최소 8초다. 이동 뒤에는 SDK 반환을 목표와 비교해, 어긋나면 다음 쓰기를 막는다. 이 비교는 축 실측이 아니다.
2. 표는 `base_link` z=0을 작업대로 가정한 모델 값이고 `hover`도 이 가정에 의존한다. 첫 접근 전에 베이스와 작업대의 높이 관계, DaBai 본체 여유를 눈으로 확인한다. 작업대에서 충분히 높은 자세부터 단계적으로 내려 실제 높이를 보고, 다르면 `z_grasp_mm`를 고쳐 표를 다시 만든다. 이 높이 탐색은 `session ladder`로 z+60, 40, 25, 15, 8, 4, 0 순서이고 단계당 쓰기 5회다. 단계마다 사용자 관찰을 `session observe`로 기록해야 다음 단계로 간다. 자세와 명령 수는 세션 승인 범위에 적는다.
3. 표 항목 전체를 J1 양끝·중앙, J5 양끝에서 `park→hover→grasp→hover→park`로 빈 그리퍼 수행한다.
4. 이상을 보고하면 즉시 끝난다. 같은 기록으로는 재개할 수 없다. 연결 단절로 중단된 경우도 같다. 팔 상태를 확인하고, 필요하면 그 조합을 표나 범위에서 뺀 뒤 구성 버전을 올려 새 기록으로 처음부터 다시 한다.
5. 빈 그리퍼, 낮은 자세에서 전원 차단 거동을 1회 기록한다.

통과하면 `verified_g0a: true`와 구성 버전, 표 해시를 기록한다. 표가 바뀌면 G0a를 다시 한다.

### G0b 저장 q 재생

`g0_runner sheet --gate G0b --seed 1`로 시험표를 만들어 저장하고, 실행 전에 커밋한다. 실패 셀을 제외하거나 재시도하지 않는다. 중단된 시도는 분모에 남는다. 물체를 쥐는 동안에는 낙하받이를 쓴다.

### G0c 라벨→표 재생

같은 시험표를 `mode=label`로 수행한다. 라벨에서 복원한 명령이 원래와 다르면 즉시 중단한다.

### G0d 허용 오차

`g0_runner sheet --gate G0d`. 판정은 없고 `tol_r`, `tol_lateral`, `tol_ψ`를 산출한다. 240회라 위험 R1에 따라 G0a·G0b 주기를 잰 뒤 범위를 다시 정한다. r 오프셋은 표 항목으로만 만들 수 있어 명목값과 다르다. 해석에는 기록된 `actual_r_offset_mm`를 쓴다.

### G0e 운영

G0b 기록에서 성공 표본당 시간을 집계한다. 카메라 재연결 1회와 낙하 판별력(그리퍼 판독, 이미지 차이)을 측정한다. 그리퍼 판독이 물체 유무를 구분한다는 것은 아직 가정이다.

## 5. Codex 잔여 항목의 처리

| 항목 | 결정 | 상태 |
| --- | --- | --- |
| B3 G0a 범위 | 표 전체×J1 3×J5 2. 실행 범위는 이 구간으로 제한 | 구현 |
| M4 `tol` 집계 | 셀·부호별로 작은 오프셋부터 연속 ≥4/5인 최대값, 그중 최솟값. 전부 실패면 0 | 구현 |
| M4 비교식 | S1 전에 확정: 위치 오차를 `r`와 횡방향으로 나눠 각 p90을 각 `tol`과 비교하는 안 | 예정 |
| M5 선택 규칙 | G1 전에 확정: A/B는 고정 검증셋의 위치 p90 기준, 5% 이내면 단순한 B | 예정 |
| M6 분할 | G1 전에 확정: 셀 단위, G1 검증 셀은 G2 학습에 넣지 않음 | 예정 |
| M7 모델 명세 | S1 전에 확정: 채널별 정규화, 온도, 출력 차원 | 예정 |

위 "예정" 칸은 제안이고, 확정할 때 해당 단계 실행 전에 커밋한다.
