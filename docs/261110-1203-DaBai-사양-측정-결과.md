# DaBai DCW2 사양 측정 결과 (1차, 배치 없는 항목)

2026-11-10 12:02 KST(Mac 시계). **팔 명령 0건, 관절 조회 0건.** Jetson에서 `orbbec_camera` 드라이버만 띄워 12초 측정하고 종료했다. 팔은 `park`, 그리퍼 100, 전원 켜짐 상태였다. 측정 코드는 `scripts/dabai_probe.py`다.

시리얼 `CH8R3620170`, 펌웨어 `RD1017`, SDK `v1.10.18-20250103-27bf2f6`(드라이버 로그). 런치는 `dabai_dcw2.launch.py`, 인자는 `camera_name:=dabai enable_point_cloud:=false enable_colored_point_cloud:=false enable_ir:=false`이고 나머지는 기본값이다(노출은 `enable_color_auto_exposure` 기본 `false`, 색 노출 `-1`).

## 2. 이 측정으로 알게 된 것

- **`park` 자세에서 DaBai는 작업대를 보지 않는다.** 한 장 영상(`data/dabai/s1/color.png`, 커밋 대상 아님)에는 흰 벽 또는 천장 평면과 좌측 가장자리의 물체만 보인다. 깊이 중앙값 1261 mm의 평면이 영상 대부분이다. 작업 영역을 보려면 `hover` 같은 다른 자세가 필요하다. 이 판단은 영상을 눈으로 본 것이고 방향을 각도로 재지 않았다.
- 컬러와 깊이의 화각이 다르다. 깊이가 훨씬 넓다(92.6° 대 67.5°). 컬러 좌표에 맞추려면 정합(depth_registration)이 필요하다. 이번에는 끄고 측정했다.
- 장면 안 가까운 물체(좌측)에서 깊이 394~396 mm가 나왔다. 이 값이 DaBai의 **최소 유효 거리**를 말하지는 않는다. 더 가까운 곳에 대상이 없었기 때문이다.

## 3. 아직 측정하지 못한 것 (플랜 H1·H4가 요구하는 값)

| --- | --- | --- |
| 최소 유효 깊이 거리 | 평평한 대상을 렌즈 앞 알려진 거리에 둔다 | 미측정 |
| 깊이 정확도(자 대비) | 같은 시험 | 미측정 |

| hover 높이에서 그리퍼가 시야에 들어오는지 | 팔을 hover로 이동(쓰기 있음, 세션 승인 필요) | 미측정 |
| 드라이버 시작부터 첫 프레임까지, 촬영→Mac 전송 지연 | 반복 실행 | 미측정 |
| 지원 모드 목록과 다른 해상도 | 드라이버 인자를 바꿔 시험 | 미측정 |

## 4. 과거 기록·판매 정보와의 비교

- 판매점 페이지(openelab.io)의 「Dabai」 사양: 작동 거리 0.3~3 m, 1 m에서 정밀도 ±6 mm, 깊이 화각 67.9°×45.3°, 컬러 1920×1080. 공식 데이터시트는 찾지 못했다. **이 장치는 `DCW2`(USB `2bc5:0561` 컬러, `2bc5:06a0` 깊이)이고 판매점 표의 모델과 같은지 확인하지 못했다.** 이번 측정의 깊이 화각 92.6°×66.4°는 그 표(67.9°×45.3°)와 크게 다르다. 같은 장치의 다른 모드인지, 다른 모델인지 구분하지 못했다. 판매점 수치를 이 장치의 사양으로 쓰지 않는다.
- 과거 프로젝트(`simple-vision-tech-poc`)는 같은 시리얼 `CH8R3620170`을 썼고 컬러 노출 포화 이슈가 있었다(`docs/261108-2030-DaBai-컬러노출포화-이슈보고서.md`). 이번 측정은 노출을 건드리지 않았고 노출 값도 읽지 않았다.

## 5. 플랜에 미치는 영향 (사실 범위만)

`docs/261110-1153-최신기술-적용-플랜-하드웨어제약만.md`의 H1은 「DaBai 최소 촬영 거리와 그리퍼 시야」다. 이번 측정은 H1의 답을 주지 않는다. `park`에서 작업대를 보지 못하므로, H1은 hover 자세 또는 사람이 렌즈 앞에 대상을 두는 측정이 필요하다. 후자는 팔을 움직이지 않는다.
