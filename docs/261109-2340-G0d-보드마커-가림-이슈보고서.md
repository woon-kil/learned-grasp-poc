# G0d 보드 마커 가림 이슈보고서

작성: 2026-11-09 KST. 쓰기 0건.

## 현상

윗면 마커 사전 시험에서 C 위치 반대 방향 값이 비어 불합격했다. 조사해 보니 시험 자리만의 문제가 아니었다. **플랜 v6이 기준으로 삼은 보드 마커 id 1이 실제 놓는 자리에서 블록에 가려진다.** G0b-9에서 J1 90인 사진의 결과다.

```text
cal5-00-r3-j90-p60 id1 True
cal5-03-r5-j90-p90 id1 False
cal5-09-r8-j90-p90 id1 False
cal5-08-r9-j90-p60 id1 False
c00-t0 r0 True
```

G0b·G0c의 J1 70·110 셀과 r0 J1 90 셀은 id 1이 전부 잡혔다(120/120). J1 90의 r5 이상만 잃었다. r5, r8은 사진에서 블록 끝이 id 1을 덮는 것을 확인했고, r9는 검출 결과만 봤다.

`G0d-0`과 1차 셀은 r_index 1, 4, 7, J1 90, J5 90이다. r7은 r5·r8 사이이고 r4는 r3·r5 사이인데 **둘 다 찍은 적이 없다.** 그대로 실행했다면 배치 확인이 검출 실패로 멈춰 해당 셀이 미완료로 끝났을 가능성이 크다.

## 원인

플랜 v6을 쓸 때 id 1의 위치와 셀 위치가 겹치는지 확인하지 않았다. id 1 검출이 끝면 마커 측정에서 안정적이었다는 결과를 그대로 옮겼다. 이미 있던 G0b-9 사진으로 쓰기 없이 확인할 수 있었던 일이다. Codex 검토 5회에서도 잡히지 않았다. 사전 시험 자리도 눈대중으로 정해 셀과 일치시키지 않았고, C에서 우연히 드러났다.

## 수정

아직 수정하지 않았다. 현재 계약의 불합격은 그대로 둔다. 새 플랜 후보는 다음이다.

1. 위치 기준을 사진 바깥쪽 큰 마커(`DICT_4X4_50` id 0, 1, 3)로 바꾼다. 놓는 자리와 떨어져 있다.
2. 각도는 카메라 사진에서 id 7만으로 잰다.
3. 새 계약을 만들어 **새 사진**으로 판정한다. 실제 셀과 겹치는 자리, id 1을 가리는 자리를 넣는다.

기존 사진 탐색 결과다. 위치는 프레임별 사진 좌표 평균이다. 판정 근거가 아니라 후보를 고른 근거다. 잡음은 카메라·마커 쌍의 값이고, 놓인 블록을 이 기준으로 잰 값은 아직 없다.


## 교훈

- 측정 기준을 정할 때는 그 기준이 실제 동작 위치에서 보이는지 있는 사진부터 확인한다.
- 사전 시험 자리는 실제 위치와 겹치게 고른다. 눈대중 자리는 위험을 놓친다.
- 시험자가 하기 어려운 절차는 데이터 품질 문제다. 이번 첫 촬영은 각도 맞추기 때문에 중단됐고, 끝 1 cm 밀기로 바꾸니 끝까지 찍혔다.
