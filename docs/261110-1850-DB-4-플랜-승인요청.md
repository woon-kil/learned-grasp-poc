# DB-4 블록 윗면 마커 검출·거리 — 측정 플랜과 승인 요청 (초안)

작성: 2026-11-10 KST, v2(사용자 요청 advisor 1차 반영). 실행 전 기록이다. **지금은 승인 전이고 팔에 명령을 보내지 않았다.** 앞선 확인: `docs/261110-1843-L3-마커-거리-사전확인-결과.md`(보드 마커, 저장 영상, 쓰기 0건). 사용자 답변: 블록 윗면 마커는 그대로 붙어 있고, 검은 테두리 한 변은 25 mm다. **푸시는 이 측정이 끝난 뒤 함께 한다**(사용자 지시).

## 1. 목적

플랜 §3.4 L3(DaBai 컬러+마커)가 쓸 **블록 윗면 마커(AprilTag 36h11 id 7)** 가 `hover`·`grasp`의 DaBai 컬러 영상에서 검출되는지, 마커 크기로 구한 거리가 어떤지를 본다. 블록 윗면은 DaBai 깊이의 사양 최소 거리 아래 구간이라 컬러+마커가 필요한 구간이다. 판정 게이트가 아니고 사실 기록이다.

## 2. 설계

- **자세와 명령**: DB-3과 같다. `session dabai-view`(`park→hover→grasp→hover→park`, `r_index 4`, J1 90, J5 90, 그리퍼 열림 SDK 100, 닫지 않음), `write6` 5회. 코드 변경 없음.
- **블록 배치**: 윗면 마커가 붙은 블록을 **눕혀서**(윗면 60×30 mm가 위) 베이스 중심에서 앞으로 195~225 mm, 좌우 중앙에 놓는다. **긴 변이 좌우**. 손끝 금지 구역(y 110~170 mm, 모델 TCP y≈139 mm)과 닿지 않는다. 배치 안내 `results/DaBai/db4-block-zone.svg`(모델 좌표, 자로 재서 놓는다).
  - 블록을 손 사이에 두지 않는 이유: 열린 손(개방 간격 약 37~43 mm, 블록 폭 약 30 mm) 사이에 정확히 넣으려면 배치 오차가 곧 손끝 충돌이다. 이 시험은 마커 검출과 거리만 보므로 DB-3처럼 손끝 구역 밖에 둔다.
  - 모델상 간격: 블록 높이 30.05 mm(2026-11-09 사용자 측정, `docs/HARDWARE-FACTS.md`, 윗면 마커 두께는 미확인)에서 `grasp` DaBai 최저점(약 111 mm) 위로 약 80 mm가 남는다(`scripts/db3_clearance.py`와 같은 계산, 모델 값, 여유 20 mm 차감 후 양수). 케이블은 모델에 없다.
- **보드 마커 병행**: 같은 영상에 보드 마커(id 1, 검은 정사각형 한 변 20 mm, 작업대 면)도 보이게 한다. 블록 마커를 가리지 않는다. **높이 확인은 단순식이 아니라 `solvePnP`로 한다.** 광축이 수직이 아니라서(모델상 `hover` 약 16°, `grasp` 약 7°) 두 마커의 단순 거리 차이는 높이와 다르다. 두 마커 모두 `cv2.solvePnP(..., SOLVEPNP_IPPE_SQUARE)`로 푼다(객체점은 aruco 코너 순서, K와 `probe.json`의 8계수 d를 그대로). **높이 = n_board · (t_block − t_board)**(n_board는 보드 마커 법선). 두 법선 사이 각도와 재투영 오차도 보고한다. 단순식은 보조 지표다. 이 확인은 모델 거리에 의존하지 않는다.
- **크기 불확실도**: 마커 크기는 자로 잰 값이라 ±0.5 mm(거리 ±2~2.5%)이고, 높이 확인이 ±5 mm 정도 퍼진다(블록 높이 약 30 mm의 약 17%). 블록 마커 크기 기록이 24.98(설계) / 25.39(이전 측정) / 25(이번 측정) mm로 셋이다. **캘리퍼스가 있으면 두 마커를 실행 전에 다시 재서 알려 달라(쓰기 0건).** 없으면 이 불확실도를 결과에 그대로 적는다.
- **촬영**: DB-3과 같다. 도착 줄마다 드라이버 `start enable_ir:=true` → 프로브 12초 → `stop` → 신호 파일.

## 3. 분석 정의 (실행 전 고정)

- 검출: OpenCV `aruco`, `DICT_APRILTAG_36h11`, id 7(블록)과 id 1(보드), **빨강 채널** 영상(사전 확인에서 회색 영상은 과노출 장면에서 놓쳤다). 회색 영상 결과도 함께 싣는다.
- 변 길이: 검출 코너 4변 평균(화소). 거리 = fx 479.07 × 실제 한 변 / 변 화소(블록 25 mm, 보드 20 mm, 사용자 측정).
- 보고: 검출 여부, 변 길이, 거리, **보드 거리 − 블록 거리와 사용자가 잰 블록 높이의 차이**, 모델 계산과의 차이. 자세별 한 세트씩이다.
- 합격선·기대값은 없다. **기대 화소 수와 거리는 사용자에게 알리지 않는다**(판독값 유도 금지). 다만 앞선 답변에서 블록 윗면 거리(약 142 / 94 mm)를 이미 알렸으므로 결과 해석의 한계에 적는다.
- **초점·검출 실패**: `grasp`에서 블록 윗면까지 약 95~100 mm는 컬러 카메라의 최소 초점 거리를 재지 않은 구간이다. 검출이 안 되면 그대로 기록하고 원인 후보(흐림, 시야 밖, 노출)를 적는다. **재시도하지 않는다.**

| 게이트 | `DB-4`. 판정 게이트가 아니다 |

| 대상 | `r_index 4`, J1 90, J5 90, 그리퍼 열림(SDK 100), 윗면 마커 블록을 구역에 눕혀 둠, 닫지 않음 |

| 세션 중단 | 조회 불일치, 연결 단절, `None` 재발. 안전 위반은 자동 쓰기 없음. 재개는 새 승인 |
| 시작 조건 | Jetson에 다른 `jetson_arm_server`·드라이버 없음, 남은 쓰기가 있는 다른 승인 없음, 시작 전·후 조회. **블록을 놓은 뒤 자리 확인 사진 1장**(사용자 휴대폰으로 위에서 보드 전체가 보이게, 또는 Gemini 한 장은 p620을 다른 세션이 쓰지 않을 때). 쓰기 0건 |
| 만료 | 승인한 날 23:59 KST |

사용자에게 받을 것: 「승인, 블록 높이 ○○ mm, 시작 확인, 그리퍼 ○○도」, 블록이 SVG 자리에 있고 손끝 금지 구역과 보드 마커 주변이 비어 있다는 확인, 끝 온도와 이동 중 관찰.

## 5. 하지 않는 것

닫기·집기, 다른 r_index·J1·J5, 표 변경, 새 전이, 새 코드. 보드 마커와 바깥쪽 4X4 마커, Gemini 스탠드, 보드 종이를 건드리지 않는다. 이 결과로 L3 채택 여부를 정하지 않는다.

## 검증 근거

코드 변경 없음, 장치 사용 없음. 사용한 사실: 보드 마커 사전 확인(`docs/261110-1843-L3-마커-거리-사전확인-결과.md`), DB-3 간격 계산(`scripts/db3_clearance.py`), DB-3의 세션·대기 규칙, 사용자 답변(블록 마커 그대로 있음, 검은 테두리 한 변 25 mm). 모델 값은 모델이라고 표기했다.
