# DB-3 DaBai 최소 유효 거리 — 표적면을 높이는 측정 플랜과 승인 요청 (초안)

작성: 2026-11-10 KST. 실행 전 기록이다. **지금은 승인 전이고 팔에 명령을 보내지 않았다.** 앞선 결과: `docs/261110-1638-DB-1-DaBai-작업거리-측정-결과.md`, `docs/261110-1656-DB-2-DaBai-깊이-원인분리-결과.md`.

## 1. 목적과 방법 선택

DB-2에서 DaBai 깊이는 `hover`(약 170 mm)에서 안정적으로 유효했고 `grasp`(약 120 mm)에서는 중앙 영역의 약 7.6%만 유효했다. 그 사이에서 깊이가 언제 사라지는지, 그리고 깊이값이 실제 거리 변화를 따라가는지(정확도) 알고 싶다.

| 안 | 판단 | 이유 |
| --- | --- | --- |
| `hover`와 `grasp` 사이 새 자세를 만든다 | 제외 | 허용 자세 표 밖이고 새 드라이런이 필요하다(AGENTS 4번). 비용이 크다 |
| **표적면을 높인다**(팔은 DB-2와 같은 자세) | **채택** | 표 안의 자세만 쓴다. 코드 변경 없음(`dabai-view` 그대로). 렌즈에서 표적까지 거리가 물체 두께만큼 줄어든다. 두께는 자로 재서 알 수 있다 |
| 판을 공중에 든다 | 제외 | 사용자 요청으로 어렵다 |

핵심 이점: 같은 자세에서 물체를 올리기 전후의 **깊이 중앙값 차이(Δ)** 를 두께와 직접 비교한다. 모델 원점·광축 기울기·DaBai 원점 차이에 의존하지 않는다.

## 2. 필요한 것과 제약

- **물체 2~3개**: 윗면이 평평하고 **가로 200 mm × 세로 90 mm 이상**, 두께 약 10, 20, 30 mm(최대 30 mm). 책, 단단한 판, 상자 등. 두께는 사용자가 자(또는 캘리퍼스)로 재서 알린다. 윗면은 무광, 색은 흰색·밝은색이 낫다(IR 반사 문제를 줄이려는 일반 원칙이고 이 장치에서 확인하지 않았다).
- **놓는 위치**: `results/DaBai/db3-object-zone.svg`(모델 계산, 손끝 금지 구역 y 110~170 mm, 놓는 구역 y 175~265 mm). **물체가 손끝 금지 구역에 닿으면 안 된다.** 손끝은 `grasp`에서 작업대 위 20 mm까지 내려온다.
- 최대 두께 30 mm에서도 `hover` 손끝(모델 TCP 높이 57 mm)과의 간격은 약 27 mm, DaBai 렌즈 축 높이(모델 약 166 mm, `grasp` 약 124 mm)와는 충분하다. 이 간격은 모델 값이고 실측이 아니다.

## 4. 분석 정의 (실행 전 고정)

- 영역·유효 기준은 DB-1·DB-2와 같다(전체 640×400, 중앙 열 160~479·행 100~299, 깊이 > 0, p05·중앙값·p95). 기준 영상은 DB-2의 C1(물체 없음, 두께 0)이다.
- 보고 값: 물체 두께 t(사용자 측정), 자세별 중앙 유효 비율과 중앙값, **중앙값 변화 Δ = 중앙값(두께 0) − 중앙값(두께 t)**, Δ − t.
- 물체가 중앙 영역을 덮는지는 영상으로 눈으로 확인해 「덮음·일부·못 덮음」으로 기록한다. 못 덮은 영상은 Δ 계산에서 제외하지 않고 그대로 보고한다.
- 합격선과 기대값은 없다. 기대값을 사용자에게 알리지 않는다.

## 5. 하지 않는 것

- 닫기, 집기, 다른 r_index·J1·J5, 표 변경, 새 전이, 새 코드.
- 줄자로 렌즈 높이 측정(DB-1과 같은 이유). 두께만 잰다. 작업대에서 윗면까지 두께는 팔에서 먼 곳에서 잰다.
- 이 결과로 L3 채택 여부를 정하지 않는다.

## 6. 위험

| 위험 | 대응 |
| --- | --- |
| 물체가 손끝·DaBai에 닿음 | 손끝 금지 구역과 최대 두께 30 mm 제한, 모델 간격 약 27 mm(`hover`, 손끝) |
| 물체가 움직여 손끝을 가로막음 | 놓는 구역 가장자리에 고정하지 않으므로 평평하고 무게가 있는 물체를 쓴다. 이동 후 영상에서 위치를 확인한다 |
| 사용자의 손이 팔 근처에 있음 | 교체는 회 사이 park에서만. 세션 중 손 금지 |
| 구성 높이·표 가정(R2) | 이 측정은 표 자세를 그대로 쓰므로 새 가정이 없다. 물체가 있어도 팔이 가는 관절은 바뀌지 않는다 |

## 7. 승인 후 순서

1. 사용자 답변 「승인, 두께 ○○ mm, 시작 확인, 그리퍼 ○○도」(회마다). `runs/DB-3/approval.json`과 승인 내역을 만들어 실행 전에 커밋한다.
2. `load_approval`, 시작 전 조회, Jetson 확인.
3. 물체 한 개 회: 드라이버 `start enable_ir:=true` → `session dabai-view` 백그라운드 → 도착 줄마다 `probe` → 신호 → `stop` → 종료 후 조회.
4. 결과 문서와 `PROJECT-STATUS.md` 갱신.

## 검증 근거

코드 변경이 없고 장치를 쓰지 않았다. 사용한 사실:

```text
DB-2 C1: hover 중앙 유효 1.000, 중앙값 174 mm / grasp 중앙 유효 0.076, 중앙값 124 mm
모델: hover DaBai 높이 165.5, 축 거리 약 172, 렌즈 축 바닥점 y≈205.7 / grasp 높이 123.8, y≈192.0, TCP y 138.7 → 139.7, TCP z 57.1 → 19.4
config: arrival_tol_deg 3, 표 해시 4b38b02de6f6...
```

## 검토 이력

앞선 플랜들에 대한 사용자 지시(Codex 교차검증 없이 advisor)를 준용한다. 이 문서는 advisor 검토를 아직 받지 않았다. 사용자가 DB-2에서 advisor 없이 승인했으므로 같은 방식을 쓸 수 있다.
