# G0d 윗면 마커 사전 시험 계약

작성: 2026-11-09 22:16 KST. **실행 전 고정이다.** 쓰기 0건 시험이다. 플랜 `docs/261109-2129-G0d-재설계-플랜.md` v6 「쓰기 없는 사전 시험」의 수치를 정한다. 도구 `scripts/marker_precheck.py`.

## 준비

`results/G0d/top-marker-id7-25mm.png`을 100% 크기로 인쇄하고 50 mm 선을 자로 재서 값을 기록한다. 마커 한 장을 흰 테두리까지 오려 블록 윗면 가운데에 붙인다. 쥐는 양옆 면에 넘어가지 않게 한다. 마커 한 변 실측값도 기록한다.

## 시험과 합격 기준

세 곳(A 보드 마커보다 베이스 쪽, B 보드 마커 왼쪽 옆, C 보드 마커보다 앞쪽). 자리는 눈대중이고 G0d 셀 위치와 같지 않다.

| 시험 | 촬영 | 합격 기준 |
| --- | --- | --- |
| 정지 검출 | 곳마다 10장 | 곳마다 **≥ 9/10** 검출 |
| 방향 구분 | 곳마다 안내선 기준 ±10° 각 5장 | 정지 평균과의 `image_angle` 차이 **≥ max(5°, 정지 std × 3)** |
| 거짓 성공 | 곳마다 같은 자리, 돌림, 밀림 사진. 가장자리 걸침 1회 | **자동 판정이 하나라도 성공이면 G0d 진입 금지** |
| 제거 | 곳마다 치운 사진 | 자동 판정 **성공**. 실패면 거짓 실패로 G0d 진입 금지, 판정값 재계획 |

판정값은 변화 ≥ 0.02, 노란 화소 ≤ 100으로 고정이다. 기준을 결과에 맞춰 바꾸지 않는다. 미달이면 원인을 기록하고 새 플랜으로 간다.

## 이 시험이 말하지 않는 것

- 손으로 놓은 블록이다. 복귀 경로의 배치, 실제 집기, 파지 영향은 `G0d-0`에서 본다.
- **조명 변화를 넣지 않는다.** 플랜은 포함을 요구했으나 쓰기 없는 짧은 시험으로는 만들 수 없어 `G0d-0`의 묶음 경계 사진에서 본다. 이 차이를 여기 적어 둔다.
- 안내선 ±10°는 손으로 맞춘 값이고 mm·도 정확도를 재지 않는다. 구분 가능성만 본다.
- 분석은 Mac의 OpenCV로 돈다. 실행 경로로 정한 p620은 **OpenCV 4.5.4**이고 API와 검출이 다를 수 있다. 실행기 구현 때 같은 사진으로 대조한다.

## 개정 1: 돌리는 방법 (사진 분석 전)

첫 촬영(22:33~22:38)은 A 전체와 B 정지 사진까지 찍고 사용자가 중단했다. 각도계 없이 ±10°를 맞추기 어려웠고, `-10도(처음 기준)` 안내문이 모호했다. 이 사진은 **분석하지 않은 채** `runs/marker-top-aborted-1/`에 보존하고 판정에 쓰지 않는다. 판정은 처음부터 다시 찍은 사진으로만 한다. 이 결정은 사진을 보기 전에 내렸다.

위 표의 「안내선 기준 ±10°」를 다음으로 바꾼다. 합격 기준은 바꾸지 않는다.

- 한쪽 방향: 블록 한쪽 끝은 그대로 두고 다른 쪽 끝을 옆으로 약 1 cm 민다. 윗면 길이 60.33 mm에서 약 9.4°다(계산값, 눈대중이라 실제 각도는 재지 않는다).
- 반대 방향: 같은 끝을 반대쪽으로 약 2 cm 밀어 처음보다 반대로 약 1 cm가 되게 한다.
- 인쇄물의 각도 안내선은 쓰지 않는다.

밀림 사진은 처음 방향으로 되돌린 뒤 돌리지 않고 옆으로 민다.
